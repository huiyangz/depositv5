# ST092 登记代办人信息

## 目标与范围

ST092 是存款业务组件（com.dcits.depsit / deposit-service）的交易执行步骤。本步骤在代办人证件号码不为空时，将代办人信息登记到代办人登记表（RB_COMMISSION_REGISTER），并按输出契约返回登记结果信息。

**范围内**：

- 登记条件判定（仅依据代办人证件号码是否为空）。
- 为空时不登记、不为空时新增登记记录及 14 项业务字段的写入映射。
- 步骤输出契约（16 个输出字段的取值与空值语义）。
- 成功标志与失败传播（无业务失败场景，失败仅由技术异常传播表达）。

**不在范围内**：

- 代办人信息的查询、修改、删除（正文仅要求登记）。
- 代办人身份核实流程本身（核实结果、核实电话号码等仅作为登记输入透传登记）。
- 输入必填性的运行时校验及其错误返回（必填性是输入契约，需求未定义校验行为，见"验收范围与明确不覆盖的事项"）。
- 与其他组件内步骤的调用编排（本步骤无组件内步骤调用，补充说明仅含枚举绑定）。

### 术语与空值语义

- **"不为空"**：指字段值非 null 且非空字符串（长度大于 0）。反之，null 与空字符串均为"为空"。
- **输出字段为空**：取值为 null（输出契约全部字段为非必填，允许为空）。
- 输入字段空值（null）按原样登记到对应记录字段，不转换、不补默认值（正文与补充说明均未定义默认值）。

### 依赖与实体访问

- **实体访问**：代办人登记表（RB_COMMISSION_REGISTER），本步骤为**新增登记记录**（写入），不查询、不修改已有记录。具体持久化方法需求未约束（工程数据服务接口 `IRbCommissionRegisterBcc` 提供 create / createSelective 等写入能力）。
- **表结构技术约束**（来源：数据结构 `RbCommissionRegisterEO` / `IRbCommissionRegisterBcc`，仅作技术约束，不是业务规则来源）：
  - 表主键为（channelSeqNo, clientNo），即（渠道流水号, 客户号）。
  - 表非空字段包括：createTimestamp、internalKey、channelSeqNo、clientNo、lastUpdTimestamp。其中渠道流水号、客户号、账户内部键值由本步骤输入提供；创建/修改时间戳属于技术字段，需求未约定其业务取值口径。
- **枚举绑定**（来源：需求"补充说明"，取值域以对应枚举类为准）：
  - 代办人证件类型 → `com.dcits.depsit.enums.ThawDocumentType2`（证件类型，示例：VALUE_110001 = "110001" 居民身份证）。
  - 国家 → `com.dcits.depsit.enums.IssCountry`（国家和地区，三位字母码，示例：CHN = 中华人民共和国）。
  - 代办人关系类型 → `com.dcits.depsit.enums.CommissionRelation`（代办人关系，取值为规范常量：VALUE_0 = "0" 亲子关系、VALUE_1 = "1" 夫妻关系、VALUE_2 = "2" 兄弟姐妹、VALUE_3 = "3" 其他）。
- **无组件内步骤调用**：需求补充说明未声明对其他步骤/规则的调用，本步骤不依赖其他正式 Spec。

## Requirements

### Requirement: REQ-001 证件号码不为空时登记代办人信息
来源：docs/requirements/ST092.md 步骤描述 第 1 条；输入表（channelSeqNo、clientNo、internalKey 必填）；已接受的需求处理结论（登记字段清单以正文 14 项为准）。

当 {代办人证件号码}（commissionDocumentId）不为空（非 null 且非空字符串）时，系统 SHALL 在代办人登记表（RB_COMMISSION_REGISTER）新增一条代办人登记记录，记录业务字段按下表逐项取输入值写入（14 项）；当 {代办人证件号码} 为空（null 或空字符串）时，系统 SHALL 不执行任何登记写入。

登记记录同时 SHALL 满足表结构约束：主键渠道流水号 = {渠道流水号}（channelSeqNo）、客户号 = {客户号}（clientNo），账户内部键值 = {账户内部键值}（internalKey）。除下表 14 项业务字段及上述主键/表必需字段外，正文未要求写入其他业务字段：代办原因（commissionReason）与交易参考号（reference）不在登记写入范围内（已接受的需求处理结论，处理记录不补充未写明的业务取值）；其余技术字段仅受表非空约束，需求未约定其业务取值。

#### Scenario: REQ-001-S01 证件号码不为空时登记全部字段
- **GIVEN** 步骤输入满足必填约束，且 14 项登记字段对应的输入均有值（示例数据：commissionDocumentId = "11010119920307123X"，commissionClientNo = "0000000002"，commissionClientName = "李代"，commissionDocumentType = ThawDocumentType2.VALUE_110001，commissionStartDate = 2026-01-01，commissionExpireDate = 2046-01-01，commissionClientTel = "13900000000"，country = IssCountry.CHN，commissionRelation = CommissionRelation.VALUE_1，commissionConfirmResult = "核实一致"，commissionConfirmTel = "13900000000"，commissionConfirmTime = "20260930093000"，commissionConfirmUserIdKey1 = "E0001"，commissionConfirmUserIdKey2 = "E0002"），channelSeqNo = "CS2026093001"，clientNo = "0000000001"，internalKey = 1
- **WHEN** 执行步骤 ST092
- **THEN** RB_COMMISSION_REGISTER 新增一条记录：主键（channelSeqNo, clientNo）=（"CS2026093001", "0000000001"），internalKey = 1，上表 14 项字段值分别等于对应输入值（枚举字段按枚举值对应，日期字段等于输入日期），未列入登记清单的 commissionReason、reference 不因本步骤登记动作写入

#### Scenario: REQ-001-S02 非必填登记字段为空时仍登记
- **GIVEN** commissionDocumentId = "11010119920307123X"（不为空），全部非必填登记输入（commissionClientNo、commissionRelation、commissionConfirmResult、commissionConfirmTel、commissionConfirmTime、commissionConfirmUserIdKey1、commissionConfirmUserIdKey2）均为 null，其余必填输入均有值
- **WHEN** 执行步骤 ST092
- **THEN** 仍在 RB_COMMISSION_REGISTER 新增一条记录（主键、账户内部键值及必填字段取输入值），记录中上述 7 个非必填字段为空；不因非必填字段为空而跳过登记或返回业务失败

#### Scenario: REQ-001-S03 证件号码为 null 时不登记
- **GIVEN** commissionDocumentId = null，其余输入满足必填约束
- **WHEN** 执行步骤 ST092
- **THEN** 不向 RB_COMMISSION_REGISTER 写入任何记录（本步骤不产生登记写入），步骤正常返回、不报业务失败

#### Scenario: REQ-001-S04 证件号码为空字符串时不登记
- **GIVEN** commissionDocumentId = ""（空字符串），其余输入满足必填约束
- **WHEN** 执行步骤 ST092
- **THEN** 不向 RB_COMMISSION_REGISTER 写入任何记录（空字符串与 null 同为"为空"），步骤正常返回、不报业务失败

### Requirement: REQ-002 步骤输出契约
来源：docs/requirements/ST092.md 输出表；已接受的需求处理结论（reference、commissionReason 不在登记写入范围，对应输出无值）。

系统 SHALL 按需求输出表返回 16 个输出字段，全部字段来源实体为代办人登记表（RB_COMMISSION_REGISTER）、全部为非必填（允许为空）：发生登记时，14 项登记字段（commissionClientNo、commissionClientName、commissionDocumentType、commissionDocumentId、commissionStartDate、commissionExpireDate、commissionClientTel、country、commissionRelation、commissionConfirmResult、commissionConfirmTel、commissionConfirmTime、commissionConfirmUserIdKey1、commissionConfirmUserIdKey2）SHALL 返回本次登记写入的值；reference 与 commissionReason 不属于登记写入字段（已接受结论），本步骤对应输出 SHALL 为空。未发生登记时，全部 16 个输出字段 SHALL 为空。

#### Scenario: REQ-002-S01 登记后输出登记值
- **GIVEN** 已按 REQ-001-S01 完成登记（14 项字段均有值写入）
- **WHEN** 步骤返回输出
- **THEN** 输出的 14 项登记字段与本次登记写入值一致（类型按输出契约：证件类型 ThawDocumentType2、国家 IssCountry、关系类型 CommissionRelation、两个日期为 java.util.Date）；输出 reference 为空、输出 commissionReason 为空（两者不在登记写入范围内，未写入登记记录）

#### Scenario: REQ-002-S02 未登记时输出全为空
- **GIVEN** commissionDocumentId 为空（null 或空字符串），未发生登记
- **WHEN** 步骤返回输出
- **THEN** 全部 16 个输出字段均为 null

### Requirement: REQ-003 成功标志与失败传播
来源：docs/requirements/ST092.md 失败处理（"本步骤无业务失败场景，失败仅由技术异常传播表达"）；工程步骤契约 StepResult。

本步骤无业务失败场景：登记与不登记两个分支均 SHALL 以成功结束（succeed = true，errorCode 与 errorMessage 为空），不得返回业务错误码。当步骤执行所依赖的底层调用（如登记写入的数据服务）发生技术异常时，系统 SHALL 将异常向调用方传播，SHALL NOT 将其捕获转换为业务失败返回（succeed = false 携带业务错误码）或吞没。

#### Scenario: REQ-003-S01 登记分支成功返回
- **GIVEN** commissionDocumentId 不为空且登记写入完成
- **WHEN** 步骤返回
- **THEN** succeed = true，errorCode = null，errorMessage = null

#### Scenario: REQ-003-S02 不登记分支成功返回
- **GIVEN** commissionDocumentId 为空，未执行登记
- **WHEN** 步骤返回
- **THEN** succeed = true，errorCode = null，errorMessage = null（不登记不是失败，不产生业务错误信息）

#### Scenario: REQ-003-S03 技术异常向调用方传播
- **GIVEN** commissionDocumentId 不为空，登记写入所依赖的数据服务调用抛出技术异常（如持久层运行时异常）
- **WHEN** 执行步骤 ST092
- **THEN** 该技术异常向步骤调用方传播，本步骤不将其转换为 succeed = false 的业务失败返回，也不吞没异常
