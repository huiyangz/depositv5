# ST108 检查增加限制起始日期

## 目标与范围

本任务为交易执行步骤：对上送的{开始日期}与{系统日期}（核心运行日期）、{结束日期}做区间判定——{开始日期}早于{系统日期}或晚于{结束日期}任一成立时检查结果为"不通过"，否则为"通过"，输出 [检查结果]。

- 范围内：步骤1 的两个违规条件分支、"否则"通过分支、边界（{开始日期}等于{系统日期}、等于{结束日期}）、输出 checkResult 的取值映射与恒有值语义。
- 不在范围内：起始日期判定之外的其他检查（黑名单、限额、检查限制等组件）及检查结果在交易编排中的后续使用；系统日期表 FM_DATE 数据的维护与读取；输入必填性校验。

## 正式需求来源

- `docs/requirements/ST108.md`（任务编号 ST108，版本 1，交易执行步骤）
  - 「步骤描述」步骤1（判定与返回，原文："若上送的{开始日期}小于{系统日期}或者大于{结束日期}，则返回检查结果为"不通过"，否则返回检查结果为"通过""）
  - 「输入」表（3 个字段）、「输出」表（1 个字段）、「失败处理」
  - 无「相关枚举」「补充说明」章节：checkResult 无枚举绑定（需求文本常量），无组件内步骤调用补充说明。
- 关联正式 Spec：无。本步骤为纯判定步骤，不调用组件内其他步骤；`docs/specs/` 下无本任务依赖的已合并 Spec。

## 输入、输出及依赖契约

### 输入

| 字段名 | 类型 | 必填性 | 说明 |
|--------|------|--------|------|
| runDate | java.util.Date | 必填 | {系统日期}，核心运行日期；来源实体：系统日期表（FM_DATE）核心运行日期（FM_DATE.RUN_DATE）。步骤描述未定义本步骤查询 FM_DATE 的动作，runDate 作为输入由上送方提供 |
| startDate | java.util.Date | 必填 | {开始日期}，上送；来源实体：需求未指定（不适用） |
| endDate | java.util.Date | 必填 | {结束日期}，上送；来源实体：需求未指定（不适用） |

需求未定义任一输入缺失或为 null 时的处理（「失败处理」声明无业务失败场景），本 Spec 不发明校验或报错行为，必填性由上送方保证。

日期比较口径：需求以日期概念（开始日期、系统日期、结束日期）描述，比较算子为"小于/大于"，类型为 java.util.Date。"小于"为严格早于，"大于"为严格晚于，相等不触发任一违规条件。本 Spec 的判定与验收断言按 年-月-日 粒度表达（需求未定义时刻口径，与 BR005 正式 Spec 的日期口径约定一致）。

### 输出

| 字段名 | 类型 | 必填性 | 来源实体 | 说明 |
|--------|------|--------|----------|------|
| checkResult | java.lang.String | 必填 | —（步骤1判定结果） | 检查结果，取值"通过"或"不通过"，需求文本常量，无枚举绑定 |

空值语义：checkResult 恒有值（必填），仅取"通过"/"不通过"两值之一，无其他取值、无空值情形。

调用成功标志与业务执行结果的区分：checkResult 为业务执行结果；输出 BO 继承的 StepResult（com.dcits.common.step.StepResult）succeed、errorCode、errorMessage 为调用成功标志。判定为"不通过"仍是正常返回（succeed=true、errorCode=null、errorMessage=null），不通过业务失败或错误码表达。

### 数据访问与依赖

- 本步骤为纯判定步骤：无数据表查询（含 FM_DATE——其仅作为 runDate 取值来源的溯源记录，见输入表）、无外部服务调用、无组件内步骤调用、无数据写入副作用。
- 场景中的具体日期值均为示例测试数据，不代表真实业务数据。

## Requirements

### Requirement: REQ-001 起始日期区间判定与检查结果输出

来源：`docs/requirements/ST108.md`「步骤描述」步骤1、「输出」表
系统 SHALL 以三个输入日期完成单次判定并输出检查结果：当 startDate（{开始日期}）严格早于 runDate（{系统日期}），或严格晚于 endDate（{结束日期}）时，输出 checkResult="不通过"；否则（startDate 晚于或等于 runDate 且早于或等于 endDate，含分别与 runDate、endDate 相等的边界）输出 checkResult="通过"。两个违规条件为"或者"关系，任一成立即"不通过"，条件之间无优先级与顺序要求。checkResult MUST 恒有值且仅取"通过"、"不通过"两值之一；判定为"不通过"时步骤 SHALL 仍正常返回（不构成业务失败，不设错误码）。

#### Scenario: REQ-001-S01 开始日期早于系统日期→不通过

- **GIVEN** 输入 runDate=2026-09-30、startDate=2026-09-29（早于系统日期）、endDate=2026-12-31（均为示例值）
- **WHEN** 执行 ST108 步骤
- **THEN** 输出 checkResult="不通过"；步骤正常返回（succeed=true，无错误码），不产生其他输出

#### Scenario: REQ-001-S02 开始日期晚于结束日期→不通过

- **GIVEN** 输入 runDate=2026-09-30、startDate=2027-01-01（晚于结束日期）、endDate=2026-12-31（均为示例值）
- **WHEN** 执行 ST108 步骤
- **THEN** 输出 checkResult="不通过"；步骤正常返回（succeed=true，无错误码），不产生其他输出

#### Scenario: REQ-001-S03 开始日期等于系统日期→通过（下边界）

- **GIVEN** 输入 runDate=2026-09-30、startDate=2026-09-30（等于系统日期，不构成"小于"）、endDate=2026-12-31（均为示例值）
- **WHEN** 执行 ST108 步骤
- **THEN** 两违规条件均不成立，落入"否则"分支，输出 checkResult="通过"；步骤正常返回

#### Scenario: REQ-001-S04 开始日期等于结束日期→通过（上边界）

- **GIVEN** 输入 runDate=2026-09-30、startDate=2026-12-31（等于结束日期，不构成"大于"）、endDate=2026-12-31（均为示例值）
- **WHEN** 执行 ST108 步骤
- **THEN** 两违规条件均不成立，落入"否则"分支，输出 checkResult="通过"；步骤正常返回

#### Scenario: REQ-001-S05 开始日期严格位于系统日期与结束日期之间→通过（正常路径）

- **GIVEN** 输入 runDate=2026-09-30、startDate=2026-10-15（严格晚于系统日期且严格早于结束日期）、endDate=2026-12-31（均为示例值）
- **WHEN** 执行 ST108 步骤
- **THEN** 两违规条件均不成立，输出 checkResult="通过"；步骤正常返回

## 验收范围与明确不覆盖的事项

### 验收范围

- 1 条需求、5 个验收场景，覆盖：两个违规分支的正常触发（早于系统日期、晚于结束日期）、"否则"通过的正常路径、两个边界（等于系统日期、等于结束日期）。
- 每个场景的 THEN 明确 checkResult 取值及正常返回语义，可直接推导测试断言。

验收场景是本 Spec 的测试设计依据，不是已生成的单元测试，也不是测试执行结果。

### 明确不覆盖

- 三个输入缺失或为 null 时的处理：需求标记必填但未定义校验行为，且声明无业务失败场景，本 Spec 不发明，必填性由上送方保证。
- runDate 与系统日期表 FM_DATE 实际数据的一致性校验（如上送值是否确为当前核心运行日期）：需求未定义；FM_DATE 仅作为 runDate 的取值来源溯源记录，场景以给定输入值直接断言，不需要 FM_DATE 数据准备。
- 输入间自相矛盾情形（如 endDate 早于 runDate）的专门校验或报错：需求未定义输入间约束，判定按统一规则执行（落入任一违规条件即"不通过"），不单列场景。
- 时刻（时分秒）粒度的比较口径：需求以日期概念描述、未定义时刻口径，本 Spec 断言按 年-月-日 粒度表达。
- 技术异常的传播与包装方式：需求声明失败仅由技术异常传播表达，不属于验收场景范围。
- 检查结果在维护限制等交易编排中的后续使用、FM_DATE 数据维护。
- 本任务无组件内步骤调用补充说明，该约定为不适用。
