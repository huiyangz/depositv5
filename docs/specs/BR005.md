# BR005 计算到期日期

## 目标与范围

- 目标：依据期限类型与存期期限，以核心运行日期为基准计算存款到期日期（规则类型：计算类，存款业务组件）。
- 范围：期限类型为 日(D)、月(M)、年(Y) 三种口径的到期日期计算，含月口径的月末与加月后无效日期调整、年口径的 2月29日调整。
- 不在范围：期限类型 周(W)、季(Q)、半年(H) 的到期日期口径（本需求未定义，见"验收范围与明确不覆盖的事项"）；输入非法时的校验失败行为；到期日期的时刻（时分秒）口径。

  - 规则描述 b 项（第 9-12 行）：月口径加月及月末、无效日期调整。
  - 规则描述 c 项（第 13-16 行）：年口径加年及 2月29日调整。
  - 输入表（第 18-24 行）：runDate（第 22 行）、term（第 23 行）、periodType（第 24 行）。
  - 输出表（第 26-30 行）：maturityDate（第 30 行）。

## 输入、输出及依赖契约

### 输入

| 字段名 | 类型 | 必填 | 约束与说明 |
|--------|------|------|----------|
| runDate | java.util.Date | 是 | 核心运行日期，即规则中的{系统日期}，日期计算基准。来源实体：需求未指定（不适用） |
| term | java.lang.String | 是 | 存期期限，即规则中的{期限}：纯十进制正整数字符串，不允许 0、负数、小数或带单位符号；单位由期限类型决定（日=天、月=月、年=年）。来源实体：需求未指定（不适用） |
| periodType | com.dcits.depsit.enums.TermType | 是 | 期限类型。枚举实际取值：D=日、W=周、M=月、Q=季、H=半年、Y=年；本规则仅对 日(D)、月(M)、年(Y) 定义计算结果 |

### 输出

| 字段名 | 类型 | 必填 | 约束与说明 |
|--------|------|------|----------|
| maturityDate | java.util.Date | 是 | 到期日期 |

### 口径与依赖说明

- 本规则为计算类规则：除输出 maturityDate 外，无状态变化、无外部调用、无其他副作用。
- 日期粒度：需求全部以 年-月-日 描述（{系统日期}、月末、2月29日均为日期概念）；需求未定义时刻（时分秒）口径，本 Spec 的预期结果与验收断言均按 年-月-日 粒度表达。
- 闰年：按公历（格里高利历）判定，即能被 4 整除且不能被 100 整除，或能被 400 整除的年份。
- 月末：指该日期的"日"等于其所在月份的最后一天（如 2026-02-28、2024-02-29、2026-01-31）。
- 场景中的具体日期与期限取值为示例数据；枚举绑定值 D/M/Y 为技术常量（来自 TermType.java）。

## Requirements

### Requirement: REQ-001 期限类型为"日"的到期日期计算
来源：docs/requirements/BR005.md 规则描述 a 项（第 7-8 行，原文："若{期限类型}是'日'：那么[到期日期] = {系统日期} + {期限}天"）

系统 SHALL 在期限类型为"日"（TermType.D）时，将到期日期计算为核心运行日期加 {期限} 天（maturityDate = runDate + term 天），并且 SHALL NOT 做任何月末调整或日期钳位调整。

#### Scenario: REQ-001-S01 常规加天
- **GIVEN** runDate = 2026-01-10，term = "90"，periodType = 日(D)
- **WHEN** 计算到期日期
- **THEN** maturityDate = 2026-04-10

#### Scenario: REQ-001-S02 月末日期加一天跨月
- **GIVEN** runDate = 2026-02-28（2026年2月的月末），term = "1"，periodType = 日(D)
- **WHEN** 计算到期日期
- **THEN** maturityDate = 2026-03-01（仅按天顺延进入3月，不因输入是月末而调整到3月31日）

#### Scenario: REQ-001-S03 跨年加天
- **GIVEN** runDate = 2026-12-31，term = "1"，periodType = 日(D)
- **WHEN** 计算到期日期
- **THEN** maturityDate = 2027-01-01

### Requirement: REQ-002 期限类型为"月"的到期日期计算与月末调整
来源：docs/requirements/BR005.md 规则描述 b 项（第 9-12 行，原文："若{期限类型}是'月'：那么[到期日期] = {系统日期} + {期限}月。并且若 {系统日期}是月末或加月后日期无效（如31日加到2月），那么将[到期日期]的'日'调整为该月的最后一天"）

系统 SHALL 在期限类型为"月"（TermType.M）时，将到期日期计算为核心运行日期加 {期限} 月；并且 SHALL 在满足以下任一条件时，将到期日期的"日"调整为目标月份（加 term 月后所得月份）的最后一天：
1. 核心运行日期是月末（runDate 的"日"等于其所在月份的最后一天）；
2. 加月后日期无效（目标月份不存在与 runDate 相同的"日"，如 31 日加到 2 月）。

上述两个条件均不满足时，到期日期的"日" SHALL 与核心运行日期的"日"一致。

#### Scenario: REQ-002-S01 常规加月（两个调整条件均不满足）
- **GIVEN** runDate = 2026-01-15（非月末），term = "6"，periodType = 月(M)
- **WHEN** 计算到期日期
- **THEN** maturityDate = 2026-07-15（"日"保持 15 不变）

#### Scenario: REQ-002-S02 加月后日期无效（需求原文示例：31日加到2月）
- **GIVEN** runDate = 2026-01-31，term = "1"，periodType = 月(M)
- **WHEN** 计算到期日期
- **THEN** maturityDate = 2026-02-28（2026年2月最后一天；目标月份无 31 日）

#### Scenario: REQ-002-S03 非月末且加月后日期无效
- **GIVEN** runDate = 2026-01-30（1月非月末），term = "1"，periodType = 月(M)
- **WHEN** 计算到期日期
- **THEN** maturityDate = 2026-02-28（目标月份无 30 日，调整为该月最后一天）

#### Scenario: REQ-002-S04 系统日期是月末且加月后日期有效
- **GIVEN** runDate = 2026-02-28（2026年2月的月末），term = "1"，periodType = 月(M)
- **WHEN** 计算到期日期
- **THEN** maturityDate = 2026-03-31（虽然 2026-03-28 为有效日期，仍因 runDate 是月末而调整为目标月份最后一天）

#### Scenario: REQ-002-S05 闰年2月29日（月末）加月
- **GIVEN** runDate = 2024-02-29（2024年2月的月末），term = "1"，periodType = 月(M)
- **WHEN** 计算到期日期
- **THEN** maturityDate = 2024-03-31（runDate 是月末，调整为目标月份最后一天，而非 2024-03-29）

#### Scenario: REQ-002-S06 加月跨年且目标日期无效
- **GIVEN** runDate = 2026-01-31，term = "13"，periodType = 月(M)
- **WHEN** 计算到期日期
- **THEN** maturityDate = 2027-02-28（目标月份为 2027年2月，无 31 日，调整为该月最后一天）

### Requirement: REQ-003 期限类型为"年"的到期日期计算与2月29日调整
来源：docs/requirements/BR005.md 规则描述 c 项（第 13-16 行，原文："若{期限类型}是'年'：那么[到期日期] = {系统日期} + {期限}年。并且若 {系统日期}是2月29日且到期年份不是闰年，那么将[到期日期]调整为2月28日"）

系统 SHALL 在期限类型为"年"（TermType.Y）时，将到期日期计算为核心运行日期加 {期限} 年；并且 SHALL 仅在核心运行日期是 2月29日 且到期年份（加 term 年后所得年份）不是闰年时，将到期日期调整为该年 2月28日。除该情形外 SHALL NOT 做其他调整（年口径不适用月口径的月末调整）。

#### Scenario: REQ-003-S01 常规加年
- **GIVEN** runDate = 2026-03-15，term = "2"，periodType = 年(Y)
- **WHEN** 计算到期日期
- **THEN** maturityDate = 2028-03-15

#### Scenario: REQ-003-S02 2月29日加年至非闰年
- **GIVEN** runDate = 2024-02-29，term = "1"，periodType = 年(Y)
- **WHEN** 计算到期日期
- **THEN** maturityDate = 2025-02-28（2025 年不是闰年，2月无 29 日，按规则调整为 2月28日）

#### Scenario: REQ-003-S03 2月29日加年至闰年（不调整）
- **GIVEN** runDate = 2024-02-29，term = "4"，periodType = 年(Y)
- **WHEN** 计算到期日期
- **THEN** maturityDate = 2028-02-29（2028 年是闰年，到期日期有效，不做调整）

#### Scenario: REQ-003-S04 非2月29日的月末日期加年（不做月末调整）
- **GIVEN** runDate = 2026-02-28（2026年2月的月末，但不是 2月29日），term = "2"，periodType = 年(Y)
- **WHEN** 计算到期日期
- **THEN** maturityDate = 2028-02-28（仅做加年，"日"保持 28 不变，不因 2028年2月有 29 日或 runDate 是月末而调整）

## 验收范围与明确不覆盖的事项

1. 期限类型 周(W)、季(Q)、半年(H)：规则描述仅定义 日、月、年 三个分支（第 7-16 行），这三种期限类型下[到期日期]无业务定义。按已接受的需求处理结论（第 44-86 行）：该事项已放行，后续生成与审核不得重复以这些事项阻断，且"处理记录不等同于补充了未写明的业务取值"（第 46 行），故其中记录的候选文本（"推荐"的 a-f 扩展口径与"选项"的仅限三种口径声明）均不构成已确认业务定义，本 Spec 不含这三种期限类型的计算条款、场景或行为约定，待业务确认后另行补充。
2. 输入非法时的行为：需求仅声明输入约束与必填标记（term 为纯十进制正整数字符串、不允许 0/负数/小数/带单位符号等），未定义违规时的错误输出或处理方式。本 Spec 不发明校验失败行为，输入约束以契约与场景前置条件（GIVEN）表达，不含违规输入场景。
3. 时刻（时分秒）口径：需求未定义，本 Spec 到期日期按 年-月-日 粒度验收，时间部分不断言。
4. 本 Spec 不重新执行需求审核；已放行事项不再作为阻断提出。
