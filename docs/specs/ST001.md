# ST001 检查客户是否存在限制

## 目标与范围

本步骤为交易执行步骤：按上送的{客户号}查询【客户限制表】（RB_CLIENT_RESTRAINTS），选取$限制状态$为 "A-生效" 的记录；命中多条时按$创建时间戳$从新到旧取第一条，将$限制编号$、$账户限制类型$、$限制状态$赋值到步骤输出并返回。

范围内：

- 按 clientNo 等值查询【客户限制表】
- $限制状态$ = "A"（生效）的筛选
- 多条命中时按$创建时间戳$降序取第一条
- 输出字段赋值、未命中时返回空输出
- 技术异常向上传播

不在范围内的事项见「验收范围与明确不覆盖的事项」。

## 输入、输出及依赖契约

### 输入

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| clientNo | java.lang.String | 必填 | 客户号，与 RB_CLIENT_RESTRAINTS.CLIENT_NO（VARCHAR(22) NOT NULL）等值匹配 |

### 输出

| 字段名 | 类型 | 必填 | 来源 | 说明 |
|--------|------|------|------|------|
| resSeqNo | java.lang.String | 非必填 | RB_CLIENT_RESTRAINTS.RES_SEQ_NO（VARCHAR(50) NOT NULL，主键成员） | 限制编号 |
| restraintType | com.dcits.depsit.enums.RestraintType | 非必填 | RB_CLIENT_RESTRAINTS.RESTRAINT_TYPE（VARCHAR(3) NOT NULL） | 账户限制类型，按枚举 value 与库存值一致映射 |
| restraintsStatus | com.dcits.depsit.enums.RestraintsStatus | 非必填 | RB_CLIENT_RESTRAINTS.RESTRAINTS_STATUS（VARCHAR(1)） | 限制状态，按枚举 value 与库存值一致映射；因筛选条件固定为生效，命中时恒为 A |

空值语义：三个输出字段均为非必填；未命中生效记录时步骤正常返回，三字段均为 null，不填充默认值。

### 枚举映射

- RestraintsStatus（限制状态）：A（需求用语"生效"；代码枚举注释为"已批准"，枚举值一致，业务行为不受影响，本 Spec 采用需求用语）、E（已终止）、F（未生效）。
- RestraintType（账户限制类型）：枚举 value 与库表 RESTRAINT_TYPE 存值一致映射，如 "13" → VALUE_13（挂失止付）、"70" → VALUE_70（黑名单控制专用-停止所有业务）。完整取值以枚举类 com.dcits.depsit.enums.RestraintType 为准。

### 数据与依赖关系

- 数据实体：【客户限制表】RB_CLIENT_RESTRAINTS，主键 (RES_SEQ_NO, CLIENT_NO)。本步骤使用字段：CLIENT_NO（等值查询条件）、RESTRAINTS_STATUS（筛选条件，值 "A"）、CREATE_TIMESTAMP（排序依据，VARCHAR(26) NOT NULL）、RES_SEQ_NO 与 RESTRAINT_TYPE（输出来源）。
- 本步骤无组件内步骤调用，不依赖其他任务的正式 Spec。
- 差异记录：需求表述 "A-生效" 与代码枚举注释 "已批准" 用语不同，枚举值均为 "A"，筛选行为一致，以需求为准。

## Requirements

### Requirement: REQ-001 按客户号查询生效客户限制并取最新一条
来源：docs/requirements/ST001.md「步骤描述」第 1 条
系统 SHALL 以输入 clientNo 为条件查询【客户限制表】，仅选取 $限制状态$ 等于 "A"（生效）的记录；命中多条时，SHALL 按 $创建时间戳$ 从新到旧排序并取第一条作为选中记录。

#### Scenario: REQ-001-S01 客户仅有一条生效限制
- **GIVEN** 【客户限制表】中客户号 C001（示例值）仅存在一条记录，RESTRAINTS_STATUS='A'，CREATE_TIMESTAMP='2026-09-28 10:00:00.000000'（示例值），RES_SEQ_NO='R20260928000001'，RESTRAINT_TYPE='13'
- **WHEN** 执行本步骤，输入 clientNo='C001'
- **THEN** 该记录被选中，选中记录的 RES_SEQ_NO='R20260928000001'

#### Scenario: REQ-001-S02 多条生效限制取创建时间戳最新一条
- **GIVEN** 客户号 C002（示例值）存在三条 RESTRAINTS_STATUS='A' 的记录，创建时间戳分别为 '2026-09-01 08:00:00.000000'、'2026-09-28 09:30:00.000000'、'2026-09-15 12:00:00.000000'（示例值），限制编号分别为 R1、R2、R3
- **WHEN** 执行本步骤，输入 clientNo='C002'
- **THEN** 选中创建时间戳为 '2026-09-28 09:30:00.000000' 的记录，选中记录的限制编号为 R2

#### Scenario: REQ-001-S03 非生效状态记录不参与选取
- **GIVEN** 客户号 C003（示例值）存在一条 RESTRAINTS_STATUS='E' 且创建时间戳最新的记录，以及一条 RESTRAINTS_STATUS='A' 且创建时间戳更早的记录
- **WHEN** 执行本步骤，输入 clientNo='C003'
- **THEN** 仅状态 'A' 的记录参与排序与选取；状态 'E'（或 'F'）的记录即使创建时间戳更新也不被选中

### Requirement: REQ-002 赋值并返回客户限制信息
来源：docs/requirements/ST001.md「步骤描述」第 2 条、「输出」
系统 SHALL 将选中记录的 $限制编号$ 赋值到 resSeqNo、$账户限制类型$ 赋值到 restraintType、$限制状态$ 赋值到 restraintsStatus，并作为步骤输出返回；未选中任何记录时，SHALL 正常返回且三个输出字段均为 null。

#### Scenario: REQ-002-S01 命中时输出选中记录信息
- **GIVEN** REQ-001 选中一条生效记录，RES_SEQ_NO='R20260928000001'，RESTRAINT_TYPE='13'，RESTRAINTS_STATUS='A'
- **WHEN** 执行赋值并返回
- **THEN** 输出 resSeqNo='R20260928000001'；restraintType=RestraintType.VALUE_13（value "13"）；restraintsStatus=RestraintsStatus.A（value "A"）

#### Scenario: REQ-002-S02 未命中时正常返回空输出
- **GIVEN** 客户号 C004（示例值）在【客户限制表】中无任何记录，或其所有记录的 RESTRAINTS_STATUS 均不为 'A'
- **WHEN** 执行本步骤，输入 clientNo='C004'
- **THEN** 本步骤不产生业务失败，正常返回；resSeqNo、restraintType、restraintsStatus 均为 null（依据：「输出」三字段标记非必填，「失败处理」声明无业务失败场景）

### Requirement: REQ-003 失败仅由技术异常传播表达
来源：docs/requirements/ST001.md「失败处理」（"本步骤无业务失败场景，失败仅由技术异常传播表达"）
本步骤 SHALL NOT 定义任何业务失败场景；失败 SHALL 仅由技术异常向上传播表达，本步骤不捕获、不转换。

#### Scenario: REQ-003-S01 数据访问技术异常向上传播
- **GIVEN** 查询【客户限制表】时底层访问抛出技术异常（如数据源不可用）
- **WHEN** 执行本步骤
- **THEN** 该技术异常按原样向上传播，本步骤不捕获、不转换，也不生成业务失败应答

## 验收范围与明确不覆盖的事项

验收场景是本 Spec 的测试设计依据，不是已生成的单元测试，也不是测试执行结果。

明确不覆盖：

1. 创建时间戳相同的并列记录：需求仅定义按 $创建时间戳$ 排序取第一条，未定义并列时的取舍规则，不纳入验收。
2. 库表 RESTRAINT_TYPE / RESTRAINTS_STATUS 存值无法映射到枚举常量时的处理：需求未定义，不纳入验收。
3. clientNo 缺失或为空时的校验行为：需求仅标记必填，未定义缺失时的处理，必填性由上送方保证，不纳入验收。
4. 限制类型的业务解释、限制的维护与解除等后续处置：非本步骤要求，不纳入验收。
