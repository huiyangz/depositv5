# ST082 登记交易流水

## 目标与范围

本任务为交易执行步骤：将输入的交易类型、币种、借贷标志、交易金额登记为一条【交易流水】（对公存款账户金融交易流水表 RB_BUS_TRAN_JNL），四个登记字段的值与对应输入值一一相同；登记完成后步骤输出回自该登记记录。

- 范围内：单条流水登记行为、四个字段的输入到登记映射、步骤输出字段的取值、三个枚举的取值绑定。
- 不在范围内：渠道流水号（channelSeqNo）的取值来源（需求未定义，已接受结论放行，见「验收范围与明确不覆盖的事项」）；输入缺失或非法的校验；流水其余字段（流水号、时间戳、机构等）的登记或生成；本步骤产出在后续交易流程中的使用；RB_BUS_TRAN_JNL 数据的查询、冲正与维护；枚举类取值清单维护。

### 数据访问与依赖

- 【交易流水】：对公存款账户金融交易流水表 RB_BUS_TRAN_JNL。本步骤为写入步骤：每次执行新增一条流水记录，无查询、无更新已有记录、无外部服务调用、无组件内步骤调用。
- 登记内容仅限步骤描述声明的四个字段（$交易类型$、$币种$、$借贷标志$、$交易金额$）；流水记录的其余字段（含 channelSeqNo 及主键、流水号、时间戳等）需求未要求登记，本 Spec 不约束其取值。
- 场景中的枚举取值、交易金额均为示例测试数据，不代表真实业务参数；交易类型枚举 value 与含义以枚举类为准。

## Requirements

### Requirement: REQ-001 登记金融交易流水（新增记录与四字段身份映射）

来源：`docs/requirements/ST082.md`「步骤描述」步骤1
系统 SHALL 向【交易流水】（RB_BUS_TRAN_JNL）新增一条记录，且每次执行 SHALL 恰好新增一条；记录的 $交易类型$ SHALL 登记为输入 {交易类型}（tranType）的值，$币种$ SHALL 登记为输入 {币种}（ccy）的值，$借贷标志$ SHALL 登记为输入 [借贷标志]（crDrInd，与 {借贷标志} 同一 CrDrInd 绑定）的值，$交易金额$ SHALL 登记为输入 {交易金额}（tranAmt）的值。四个登记字段与输入值完全相同：枚举按其 value 写入（如 CrDrInd.C 写入 "C"），金额原值写入、不舍入、不变换。除该四个字段外系统 MUST NOT 被要求写入其他指定值（其余字段需求未定义，不作为断言对象）。

#### Scenario: REQ-001-S01 贷记人民币现金存入登记

- **GIVEN** 输入 tranType=OthTranType.VALUE_1000（"1000"，现金存入）、ccy=Ccy.CNY（"CNY"）、crDrInd=CrDrInd.C（"C"，贷）、tranAmt=1000.00（示例，BigDecimal）
- **WHEN** 执行 ST082 步骤
- **THEN** RB_BUS_TRAN_JNL 新增一条流水记录，该记录 tranType="1000"、ccy="CNY"、crDrInd="C"、tranAmt=1000.00，四个字段值与对应输入完全一致；仅新增一条记录

#### Scenario: REQ-001-S02 借记外币现金支取登记

- **GIVEN** 输入 tranType=OthTranType.VALUE_1003（"1003"，现金支取）、ccy=Ccy.USD（"USD"）、crDrInd=CrDrInd.D（"D"，借）、tranAmt=500.50（示例）
- **WHEN** 执行 ST082 步骤
- **THEN** RB_BUS_TRAN_JNL 新增一条流水记录，该记录 tranType="1003"、ccy="USD"、crDrInd="D"、tranAmt=500.50，与输入完全一致（覆盖借贷标志另一取值、另一币种与另一交易类型，映射同为身份映射）

#### Scenario: REQ-001-S03 交易金额含分位小数原样登记

- **GIVEN** 输入 tranType=OthTranType.VALUE_1000、ccy=Ccy.CNY、crDrInd=CrDrInd.C、tranAmt=12345.67（示例，两位小数）
- **WHEN** 执行 ST082 步骤
- **THEN** 登记记录的 tranAmt 为 12345.67，与输入数值和精度完全一致，无舍入、无变换（需求未定义金额边界，边界限制不作为断言）

### Requirement: REQ-002 登记完成后的步骤输出取值

来源：`docs/requirements/ST082.md`「输出」表、「已接受的需求处理结论」
系统 SHALL 在登记完成后输出 crDrInd、ccy、tranType、tranAmt 四个字段，取值为本次登记后的【交易流水】记录对应字段值（即与本次输入一致）。channelSeqNo 为「输出」表声明的非必填输出字段（来源实体 RB_BUS_TRAN_JNL），其取值来源需求未定义且已按需求处理流程放行；本 Spec 不约束其取值，验收场景 MUST NOT 对 channelSeqNo 的值作断言。

#### Scenario: REQ-002-S01 登记成功后输出与登记记录一致

- **GIVEN** 输入 tranType=OthTranType.VALUE_1000（"1000"）、ccy=Ccy.CNY（"CNY"）、crDrInd=CrDrInd.C（"C"）、tranAmt=1000.00（示例），步骤已按 REQ-001 完成登记
- **WHEN** 读取 ST082 步骤输出
- **THEN** 输出 crDrInd=CrDrInd.C、ccy=Ccy.CNY、tranType=OthTranType.VALUE_1000、tranAmt=1000.00，均与登记记录及本次输入一致；channelSeqNo 为非必填字段，取值来源未定义，不在断言范围

## 验收范围与明确不覆盖的事项

### 验收范围

- 2 条需求、4 个验收场景，覆盖：贷记登记与借记登记的正常路径、借贷标志两取值（C/D）、多币种（CNY/USD）与多交易类型（1000/1003）的身份映射、金额含分位小数的原样登记、登记成功后输出与登记记录的一致性。
- 每个登记场景的 THEN 明确保存记录的字段级取值（枚举 value），输出场景的 THEN 明确四个输出字段取值，可直接推导测试断言。

### 明确不覆盖

- channelSeqNo 的取值来源与生成规则：原文给出上游传入、本步骤生成、删除字段三个待确认方向，已按需求处理流程放行且处理记录不等同于补充业务取值；本 Spec 按原文保留该输出字段声明，不定义其来源，验收不断言其值，后续生成与审核不得重复以该事项阻断。
- 输入缺失、为空或非法（含金额边界、币种/交易类型枚举清单外取值）的处理：需求标记必填但未定义校验行为，且声明无业务失败场景，本 Spec 不发明。
- 流水记录其余字段（主键、流水号、渠道流水号、时间戳、机构等）的取值与生成：需求未要求，不约束、不断言。
- 技术异常（如数据访问异常）的传播与包装方式：需求声明失败仅由技术异常传播表达，不属于验收场景范围。
- 本步骤产出在后续交易流程中的使用、RB_BUS_TRAN_JNL 的查询/冲正/维护、枚举取值清单维护。
- 本任务无组件内步骤调用补充说明，该约定为不适用。
