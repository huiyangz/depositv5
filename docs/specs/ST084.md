# ST084 检查存入交易类型

## 目标与范围

本任务为存款业务组件（deposit-service）的交易执行步骤：在活期现金存入交易的执行编排中，对上送的{交易类型}与"现金存入"做相等校验——{交易类型}不等于"现金存入"时，步骤以[错误码]"ER0049"失败结束；等于时，步骤以检查结果"通过"成功结束。

- 范围内：判定条件与比较基准的枚举绑定、通过/失败两条结果路径的表达、输入字段契约、交易类型枚举取值来源与别名绑定。
- 不在范围内：交易类型检查之外的其他检查（黑名单、限额、限制等组件）及活期现金存入交易的其余执行步骤；错误码"ER0049"的错误信息文案；枚举类 OthTranType 取值清单的定义与维护。

"活期现金存入时"为本步骤的所属交易语境（本步骤在活期现金存入交易中执行），不是运行时输入条件：本步骤输入仅有{交易类型}，判定只使用该输入。

## Requirements

### Requirement: REQ-001 存入交易类型检查

来源：`docs/requirements/ST084.md`「步骤描述」第 1 条
系统 SHALL 对输入{交易类型}（tranType）与"现金存入"（OthTranType.VALUE_1000，值"1000"）做相等判定：不相等时，步骤 MUST 以[错误码]"ER0049"失败结束（succeed=false、errorCode="ER0049"）；相等时，步骤 MUST 以检查结果"通过"成功结束（succeed=true、errorCode=null、errorMessage=null）。除本判定结果外，步骤 MUST NOT 产生其他输出或副作用。

#### Scenario: REQ-001-S01 交易类型等于现金存入→通过

- **GIVEN** 输入 tranType=OthTranType.VALUE_1000（"现金存入"，值"1000"）
- **WHEN** 执行 ST084 步骤
- **THEN** 相等判定成立，检查结果为"通过"：succeed=true、errorCode=null、errorMessage=null；无其他输出、无副作用

#### Scenario: REQ-001-S02 交易类型为其他业务类型→返回ER0049

- **GIVEN** 输入 tranType=OthTranType.VALUE_1003（"现金支取"，值"1003"，示例数据，代表任一不等于 VALUE_1000 的取值）
- **WHEN** 执行 ST084 步骤
- **THEN** {交易类型}不等于"现金存入"，步骤失败结束：succeed=false、errorCode="ER0049"；errorMessage 内容不作断言（需求未定义）

#### Scenario: REQ-001-S03 交易类型名称含现金存入字样但不为判定基准→返回ER0049

- **GIVEN** 输入 tranType=OthTranType.VALUE_1001（"现金存入-冲销"，值"1001"，示例数据）
- **WHEN** 执行 ST084 步骤
- **THEN** 相等判定仅对 VALUE_1000（值"1000"）成立，"现金存入-冲销"不等于"现金存入"，步骤失败结束：succeed=false、errorCode="ER0049"

## 验收范围与明确不覆盖的事项

### 验收范围

- 1 条需求、3 个验收场景，覆盖：等于判定基准的通过路径；不等于判定基准的失败路径，含一般业务类型（现金支取）与名称近似类型（现金存入-冲销，钉死精确相等语义，排除按名称前缀误匹配）两个代表性取值。
- 每个场景的 THEN 明确 StepResult 契约字段的确定性取值（succeed、errorCode、errorMessage），可直接推导测试断言。

### 明确不覆盖

- tranType 缺失（null）时的校验行为：需求标记必填但未定义处理，必填性由上送方保证，不纳入验收。
- errorMessage（错误信息）内容：需求仅定义错误码"ER0049"，未定义错误信息，不作约束、不纳入断言。
- 相等判定的实现形式（枚举常量比较或值"1000"比较）：两者等价，本 Spec 约束判定结果，不约束实现方式。
- 技术异常处理：本步骤无数据访问与外部调用，需求亦未定义，不纳入验收。
- 检查结果"通过"在活期现金存入交易后续步骤中的使用、交易编排的其余步骤、其他检查组件的行为。
- 枚举类 OthTranType 取值清单的维护；错误码"ER0049"在错误码字典中的登记与提示文案（工程内暂无该错误码定义）。
