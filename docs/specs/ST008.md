# ST008 检查是否存在现金止收限制

## 目标与范围

本 Spec 规范存款业务组件交易执行步骤 ST008：以账号为输入，检查该账户是否存在现金止收限制，输出判定标志 cashStopFlag，并在命中时输出首条命中限制记录及其限制类型的明细信息。

步骤行为由三次子步骤构成：

1. 按账号查询账户的生效限制记录（结果集，遍历全部记录）；
2. 按记录的账户限制类型查询限制类型表的生效类型记录，取得借贷方控制标志、现金标志、止付标志；
3. 逐条判定"借贷方控制标志 = C-禁止贷方 且 现金标志 = N-不允许现金"，按首条命中记录聚合输出。

在范围内：两次实体查询的条件与字段、逐条判定与首条命中聚合规则、输出契约（字段、类型、必填性、空值语义、枚举绑定）、技术异常传播。

不在范围：输入校验、cashStopFlag 的下游消费、限制数据维护、其他控制标志（转账、止付、销户等）的判定、业务失败定义。详见文末"验收范围与明确不覆盖的事项"。

## Requirements

### Requirement: REQ-001 获取账户生效限制记录

来源：ST008.md「步骤描述」第1条（查询部分）

系统 SHALL 以输入账号 baseAcctNo 与限制状态等于"A-生效"（值 "A"，RestraintsStatus.A）为条件查询【账户限制信息】（RB_BUS_RESTRAINTS），得到生效限制记录结果集；结果集 MUST 包含该账号全部生效限制记录，后续判定 MUST 遍历结果集的全部记录；每条被遍历记录 MUST 能取得限制编号（resSeqNo）与账户限制类型（restraintType）。查询为只读，MUST NOT 修改任何数据。

#### Scenario: REQ-001-S01 仅生效记录进入结果集并全部遍历

- **GIVEN** 账号 "2000010001"（示例）在 RB_BUS_RESTRAINTS 存在限制编号 RES0001、RES0002 两条限制状态 = "A" 的记录，以及限制编号 RES0003、限制状态 = "E"（已终止）的一条记录
- **WHEN** 执行本步骤，按账号查询【账户限制信息】
- **THEN** 查询条件包含 baseAcctNo = "2000010001" 且 restraintsStatus = "A"；结果集包含 RES0001、RES0002 两条记录，不含 RES0003；结果集中每条记录均可取得 resSeqNo 与 restraintType，且两条记录均参与后续类型判定遍历

### Requirement: REQ-002 获取账户限制类型生效信息

来源：ST008.md「步骤描述」第2条

对遍历中的每条生效限制记录，系统 SHALL 以该记录的账户限制类型（restraintType）与状态等于"A-生效"（值 "A"，Status.A）为条件查询【限制类型表】（RB_RESTRAINT_TYPE），取得该类型生效类型记录的借贷方控制标志（drCrCtlFlag）、现金标志（cashFlag）、止付标志（stopFlag）。未取得生效类型记录时，该限制记录 MUST NOT 判定为命中，遍历 MUST 继续处理后续记录，且该情况 MUST NOT 视为业务失败。

#### Scenario: REQ-002-S01 取得生效类型记录的控制标志

- **GIVEN** 遍历到一条生效限制记录，其 restraintType = "92"（示例类型值），且 RB_RESTRAINT_TYPE 中该类型存在状态 = "A" 的记录，其 drCrCtlFlag = "C"、cashFlag = "N"、stopFlag = "1"（造数示例值）
- **WHEN** 按该 restraintType 查询【限制类型表】
- **THEN** 查询条件包含 restraintType = "92" 且 status = "A"；取得该类型记录的 drCrCtlFlag = "C"、cashFlag = "N"、stopFlag = "1"，用于该条记录的命中判定

#### Scenario: REQ-002-S02 类型无生效类型记录时不命中并继续

- **GIVEN** 遍历到一条生效限制记录，其 restraintType = "91"（示例类型值），RB_RESTRAINT_TYPE 中该类型不存在状态 = "A" 的记录（无该类型记录，或类型记录存在但状态非 "A"，示例为状态 = "C"）
- **WHEN** 按该 restraintType 查询【限制类型表】
- **THEN** 未取得生效类型记录；该条限制记录不满足现金止收命中条件，遍历继续处理下一条生效限制记录；本情况不构成业务失败、不产生业务报错

### Requirement: REQ-003 现金止收判定与首条命中输出

来源：ST008.md「步骤描述」第1条（命中与聚合规则）、第3条；「输出」表

系统 SHALL 按结果集返回顺序逐条判定：限制记录对应的生效类型记录满足借贷方控制标志等于"C-禁止贷方"（值 "C"，DrCrCtlFlag.C）且现金标志等于"N-不允许现金"（值 "N"）时，该记录命中；两个条件 MUST 同时成立。任一记录命中时，cashStopFlag MUST 为"是"，resSeqNo、restraintType、restraintsStatus MUST 取首条命中记录的值（"首条命中记录"指结果集返回顺序下第一条命中的记录），status、drCrCtlFlag、cashFlag、stopFlag MUST 取首条命中记录对应的生效类型记录的值（故 status = "A"、drCrCtlFlag = "C"、cashFlag = "N"，stopFlag 取该类型记录止付标志原值）。无生效记录或全部记录均未命中时，cashStopFlag MUST 为"否"，且 resSeqNo、restraintType、restraintsStatus、status、drCrCtlFlag、cashFlag、stopFlag 七个输出 MUST 为空（null）。cashStopFlag 在任何正常完成路径上 MUST 有值（"是"或"否"）。

需求未规定结果集排序规则，"首条"以数据服务返回顺序为准；命中后是否继续遍历剩余记录、以及按记录还是按去重类型发起【限制类型表】查询，需求均未约束（输出不因实现选择而变化），验收不应断言命中后的类型表查询次数。

#### Scenario: REQ-003-S01 首条生效记录命中

- **GIVEN** 账号存在一条生效限制记录：resSeqNo = "RES0001"、restraintType = "92"（示例）、restraintsStatus = "A"；RB_RESTRAINT_TYPE 中类型 "92" 的生效记录（status = "A"）drCrCtlFlag = "C"、cashFlag = "N"、stopFlag = "1"（均为造数示例）
- **WHEN** 执行本步骤完成遍历判定
- **THEN** cashStopFlag = "是"；resSeqNo = "RES0001"；restraintType 为值 "92"（RestraintType 枚举）；restraintsStatus 为值 "A"（RestraintsStatus.A）；status 为值 "A"（Status.A）；drCrCtlFlag 为值 "C"（DrCrCtlFlag.C）；cashFlag = "N"；stopFlag = "1"

#### Scenario: REQ-003-S02 首条未命中、后续记录命中

- **GIVEN** 账号存在两条生效限制记录，数据服务按顺序返回：第 1 条 resSeqNo = "RES0001"、restraintType = "67"（示例），其生效类型记录 drCrCtlFlag = "A"、cashFlag = "Y"；第 2 条 resSeqNo = "RES0002"、restraintType = "92"（示例），其生效类型记录 drCrCtlFlag = "C"、cashFlag = "N"、stopFlag = "1"
- **WHEN** 执行本步骤完成遍历判定
- **THEN** cashStopFlag = "是"；resSeqNo = "RES0002"；restraintType 为值 "92"；restraintsStatus 为值 "A"；status 为值 "A"；drCrCtlFlag 为值 "C"；cashFlag = "N"；stopFlag = "1"；第 1 条记录（RES0001、"67"）的任何值不出现在输出中

#### Scenario: REQ-003-S03 两个条件仅满足其一时不命中

- **GIVEN** 账号存在两条生效限制记录：第 1 条的生效类型记录 drCrCtlFlag = "C"、cashFlag = "Y"（示例，非 "N"）；第 2 条的生效类型记录 drCrCtlFlag = "D"、cashFlag = "N"
- **WHEN** 执行本步骤完成遍历判定
- **THEN** 两条记录均未命中（判定条件为"且"，任一条件不满足即不命中）；cashStopFlag = "否"；resSeqNo、restraintType、restraintsStatus、status、drCrCtlFlag、cashFlag、stopFlag 均为 null

#### Scenario: REQ-003-S04 存在生效记录但均未命中

- **GIVEN** 账号存在两条生效限制记录：第 1 条的账户限制类型在 RB_RESTRAINT_TYPE 中无状态 = "A" 的记录（REQ-002-S02 情形）；第 2 条的生效类型记录 drCrCtlFlag = "A"、cashFlag = "Y"
- **WHEN** 执行本步骤完成遍历判定
- **THEN** cashStopFlag = "否"；resSeqNo、restraintType、restraintsStatus、status、drCrCtlFlag、cashFlag、stopFlag 七个输出均为 null

#### Scenario: REQ-003-S05 无生效记录

- **GIVEN** 账号在 RB_BUS_RESTRAINTS 不存在任何限制状态 = "A" 的记录（无任何限制记录，或仅有非生效状态的记录）
- **WHEN** 执行本步骤完成遍历判定
- **THEN** cashStopFlag = "否"；resSeqNo、restraintType、restraintsStatus、status、drCrCtlFlag、cashFlag、stopFlag 七个输出均为 null；因结果集为空，不发起任何【限制类型表】查询

### Requirement: REQ-004 无业务失败与技术异常传播

来源：ST008.md「失败处理」

本步骤 MUST NOT 定义任何业务失败场景或业务失败输出。实体查询等发生的技术异常 MUST 向调用方原样传播：不捕获、不转换、不降级，也不产生 cashStopFlag 等业务输出。

#### Scenario: REQ-004-S01 技术异常原样传播

- **GIVEN** 查询【账户限制信息】（或【限制类型表】）在执行中抛出技术异常（示例：数据访问异常）
- **WHEN** 执行本步骤
- **THEN** 该异常向调用方原样传播；步骤不捕获、不转换该异常，不构造业务失败结果，也不输出 cashStopFlag 等业务字段

## 验收范围与明确不覆盖的事项

1. baseAcctNo 缺失、空值或格式不合法的校验与报错行为——需求仅标记必填，未定义校验动作。
2. cashStopFlag 及其余输出的下游消费逻辑（交易编排对"是/否"的短路或继续处理）属调用方，不在本步骤范围。
3. 限制记录与限制类型记录的维护（新增、解除、状态变更），以及转账止收、止付、销户等其他控制标志的判定。
4. 【账户限制信息】结果集的排序规则——需求未规定排序，"首条命中"以数据服务返回顺序为准，不应对排序做断言。
5. 命中后的遍历终止时机与【限制类型表】查询次数（按记录逐条或按去重类型查询）——输出不因实现选择而变化，不做断言。
6. 业务失败码与业务报错契约——需求明确本步骤无业务失败场景。
7. stopFlag、cashFlag 的完整值域定义——需求仅使用 cashFlag = "N"（不允许现金）这一取值，stopFlag 仅原值透传；场景中的 "Y"、"1" 等均为造数示例。
