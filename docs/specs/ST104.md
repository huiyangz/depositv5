# ST104 更新累计限额

## 目标与范围

本任务为交易执行步骤：依据上游限额检查结果与累计数据，条件性地按主键更新【限额累计信息表】（RB_LIMIT_SUM_INFO）的 $限额累计金额$。当 [限额检查结果] 为"未超限"且 [限额累计金额] 大于 0 或 [限额累计笔数] 大于 0 时，以 {账号} 作为限额检查对象值（checkObjVal）、{限额场景编码} 作为限额场景编码（limitSceneNo），按主键将该记录的 $限额累计金额$ 更新为输入 [限额累计金额]，并输出该值；触发条件不满足时不执行任何更新，输出为空。

范围内：

- 触发条件的判定（[限额检查结果]="未超限" 且（[限额累计金额]>0 或 [限额累计笔数]>0），含或关系两侧与 0 边界）；
- 按主键（限额检查对象值、限额场景编码）定位记录并更新 $限额累计金额$ 的行为与更新范围；
- 输出字段 limitSumAmt 的赋值与空值语义；
- 无业务失败场景、技术异常传播的失败处理约定。

不在范围内的事项见「验收范围与明确不覆盖的事项」。

## 输入、输出及依赖契约

### 输入（全部必填）

| 字段名 | 类型 | 说明 |
|--------|------|------|
| 限额检查结果 | java.lang.String | 上游限额检查结果；按字面值与"未超限"比较。工程内无对应枚举类，"未超限"为需求文本规范常量；其他取值（如"超限"）均为示例数据，仅使条件不成立。需求未标注来源实体 |
| baseAcctNo | java.lang.String | 账号；本步骤将其作为【限额累计信息表】主键成员之一的限额检查对象值（checkObjVal）使用。需求标注来源实体：对公存款账户限制表（RB_BUS_RESTRAINTS），该标注为上游数据来源声明 |
| limitSceneNo | java.lang.String | 限额场景编码；主键成员之二（limitSceneNo） |
| clientNo | java.lang.String | 客户号；需求标注来源实体：限额累计信息表（RB_LIMIT_SUM_INFO）。本步骤的更新主键为（限额检查对象值、限额场景编码），不含客户号，步骤描述未将 clientNo 用于更新条件或输出，本步骤对其无使用 |
| limitSumAmt | java.math.BigDecimal | 限额累计金额；参与触发条件判定（大于 0，数值比较），满足条件时作为写入 $限额累计金额$ 的值 |
| 否 | java.lang.Integer | 限额累计笔数；仅参与触发条件判定（大于 0，数值比较），不作为更新内容 |

字段名"否"的说明：限额累计笔数字段在需求输入表与工程数据模型（实体 RbLimitSumInfoEO.否、DDL 列 `否 INT`）中字段名即为"否"，属数据模型既有命名技术约束，本 Spec 按原字段名记录，不更名。

必填性由上送方保证；需求未定义输入缺失、为空或非法值时的处理，本 Spec 不发明校验分支（见不覆盖事项）。

### 实体与字段映射（技术约束）

| 需求实体/字段 | 工程对象 | 表字段 | 约束 |
|---------------|----------|--------|------|
| 【限额累计信息表】 | RbLimitSumInfo / RbLimitSumInfoEO，数据服务 IRbLimitSumInfoBcc | RB_LIMIT_SUM_INFO | 主键 (CHECK_OBJ_VAL, LIMIT_SCENE_NO)，与步骤"按主键更新"一致 |

### 输出

| 字段名 | 类型 | 必填性 | 来源 | 说明 |
|--------|------|--------|------|------|
| limitSumAmt | java.math.BigDecimal | 非必填 | 限额累计信息表（RB_LIMIT_SUM_INFO）$限额累计金额$ | 更新执行时等于更新写入的值，即输入 [限额累计金额]；未执行更新时为空（null） |

空值语义推导：输出标记非必填；「步骤描述」中唯一的赋值动作是条件满足时的按主键更新，触发条件不满足时步骤不执行任何给 limitSumAmt 赋值的动作，输出为 null，不填充默认值。

### 数据访问与副作用

- 数据访问为一次按主键的条件更新（写），仅在触发条件满足时执行；条件不满足时无任何读写操作。
- 更新内容仅 $限额累计金额$ 一个字段；$限额累计笔数$（字段"否"）、$客户号$ 等其余字段需求未要求更新，MUST NOT 变更。
- 无外部服务调用、无组件内步骤调用。
- 场景中账号、场景编码、金额、笔数等具体数据均为示例测试数据，非规范常量（"未超限"除外）。

## Requirements

### Requirement: REQ-001 更新触发条件判定

来源：`docs/requirements/ST104.md`「步骤描述」第 1 条（条件部分）
系统 SHALL 在 [限额检查结果] 等于 "未超限"（String 字面值比较）且 [限额累计金额] 大于 0 或 [限额累计笔数] 大于 0（两分支为或关系，与 0 的比较为数值比较）时，判定触发条件满足并执行按主键更新（REQ-002）；其余情形（[限额检查结果] 不等于 "未超限"，或 [限额累计金额] 与 [限额累计笔数] 均不大于 0）MUST NOT 执行任何对【限额累计信息表】的更新。

#### Scenario: REQ-001-S01 未超限且金额、笔数均大于0→触发更新

- **GIVEN** 限额检查结果="未超限"，limitSumAmt=50000.00（示例，大于 0），否=3（示例，大于 0）
- **WHEN** 执行 ST104 步骤
- **THEN** 触发条件满足，执行按主键更新（更新内容与输出见 REQ-002、REQ-003）

#### Scenario: REQ-001-S02 未超限且金额大于0、笔数为0→触发更新（或分支·金额侧）

- **GIVEN** 限额检查结果="未超限"，limitSumAmt=50000.00（大于 0），否=0
- **WHEN** 执行 ST104 步骤
- **THEN** 笔数分支不成立但金额分支成立，触发条件满足，执行按主键更新

#### Scenario: REQ-001-S03 未超限且金额为0、笔数大于0→触发更新（或分支·笔数侧）

- **GIVEN** 限额检查结果="未超限"，limitSumAmt=0（不大于 0），否=3（大于 0）
- **WHEN** 执行 ST104 步骤
- **THEN** 金额分支不成立但笔数分支成立，触发条件满足，执行按主键更新，$限额累计金额$ 更新为输入值 0，输出 limitSumAmt=0（见 REQ-003）

#### Scenario: REQ-001-S04 未超限但金额、笔数均为0→不更新

- **GIVEN** 限额检查结果="未超限"，limitSumAmt=0，否=0
- **WHEN** 执行 ST104 步骤
- **THEN** 两个或分支均不成立，触发条件不满足；不执行任何对【限额累计信息表】的更新（任何记录、任何字段均不变更），步骤正常返回，输出 limitSumAmt 为空（null，见 REQ-003-S02）

#### Scenario: REQ-001-S05 限额检查结果非"未超限"→不更新

- **GIVEN** 限额检查结果="超限"（示例数据，非"未超限"），limitSumAmt=50000.00（大于 0），否=3（大于 0）
- **WHEN** 执行 ST104 步骤
- **THEN** 前置条件不成立，触发条件不满足；不执行任何更新，步骤正常返回，输出 limitSumAmt 为空（null）；即便金额、笔数均大于 0 也不触发

### Requirement: REQ-002 按主键更新限额累计金额

来源：`docs/requirements/ST104.md`「步骤描述」第 1 条（动作部分）
触发条件满足时，系统 SHALL 以 {账号}（baseAcctNo）作为限额检查对象值（checkObjVal）、{限额场景编码}（limitSceneNo）作为限额场景编码，按主键 (CHECK_OBJ_VAL, LIMIT_SCENE_NO) 定位【限额累计信息表】记录，将该记录的 $限额累计金额$（LIMIT_SUM_AMT）更新为输入 [限额累计金额]（limitSumAmt）；SHALL 仅更新 $限额累计金额$ 字段，$限额累计笔数$（字段"否"）、$客户号$（clientNo）等其他字段 MUST NOT 变更；主键不等于该二值组合的其他记录 MUST NOT 受影响。

#### Scenario: REQ-002-S01 命中主键记录更新且其余记录不受影响

- **GIVEN** RB_LIMIT_SUM_INFO 中存在三条记录（示例数据）：记录甲 checkObjVal="1002003004005006"、limitSceneNo="LS20260001"、limitSumAmt=12000.00、否=2、clientNo="C0001234567"；记录乙 checkObjVal="1002003004005006"（同账号）、limitSceneNo="LS20260002"（不同场景）、limitSumAmt=800.00；记录丙 checkObjVal="1002003004005007"（不同账号）、limitSceneNo="LS20260001"（同场景）、limitSumAmt=600.00
- **WHEN** 触发条件满足（对应 REQ-001-S01），输入 baseAcctNo="1002003004005006"、limitSceneNo="LS20260001"、limitSumAmt=50000.00，执行按主键更新
- **THEN** 仅记录甲被更新，其 LIMIT_SUM_AMT=50000.00；记录乙、记录丙的所有字段保持原值不变

#### Scenario: REQ-002-S02 仅限额累计金额字段被更新

- **GIVEN** RB_LIMIT_SUM_INFO 中记录 checkObjVal="1002003004005006"、limitSceneNo="LS20260001"、limitSumAmt=12000.00、否=2、clientNo="C0001234567"（示例数据）
- **WHEN** 触发条件满足，输入 limitSumAmt=50000.00、否=3（输入笔数仅参与触发条件），执行按主键更新
- **THEN** 该记录 LIMIT_SUM_AMT=50000.00；$限额累计笔数$（字段"否"）保持原值 2（不取输入值 3），$客户号$ 保持原值 "C0001234567"，均不变更

### Requirement: REQ-003 输出限额累计金额

来源：`docs/requirements/ST104.md`「输出」表（limitSumAmt 非必填）及「步骤描述」第 1 条
更新执行时，系统 SHALL 输出 limitSumAmt 为更新写入的 $限额累计金额$ 值（等于输入 [限额累计金额]）；触发条件不满足、未执行更新时，SHALL 正常返回且 limitSumAmt 为空（null）。

#### Scenario: REQ-003-S01 更新执行→输出更新后的限额累计金额

- **GIVEN** 触发条件满足（对应 REQ-001-S01），输入 limitSumAmt=50000.00，按主键更新成功执行，记录 LIMIT_SUM_AMT 写入 50000.00
- **WHEN** 步骤返回输出
- **THEN** 输出 limitSumAmt=50000.00（BigDecimal，等于输入 [限额累计金额]，即更新后的 $限额累计金额$）

#### Scenario: REQ-003-S02 未执行更新→输出为空

- **GIVEN** 触发条件不满足（对应 REQ-001-S04 或 REQ-001-S05），未执行任何更新
- **WHEN** 步骤返回输出
- **THEN** limitSumAmt 为 null（依据：「输出」标记非必填，步骤描述中无其他给该字段的赋值动作）；该情形不构成步骤失败（见 REQ-004）

### Requirement: REQ-004 无业务失败场景、技术异常原样传播

来源：`docs/requirements/ST104.md`「失败处理」（"本步骤无业务失败场景，失败仅由技术异常传播表达"）
本步骤 MUST NOT 产生业务失败场景：全部业务情形（触发更新与不触发更新）均以步骤成功结束，不设置业务错误码与错误信息；失败仅由技术异常表达，技术异常 SHALL 按原样向调用方传播，本步骤不捕获、不转译为业务失败结果。

#### Scenario: REQ-004-S01 全部业务情形均成功结束

- **GIVEN** 本步骤任一业务情形（REQ-001 的触发与不触发路径，含更新执行与输出为空）
- **WHEN** 步骤执行完成
- **THEN** 步骤结果为成功（succeed=true），业务错误码与错误信息为空（errorCode=null、errorMessage=null）

#### Scenario: REQ-004-S02 技术异常向调用方传播

- **GIVEN** 按主键更新【限额累计信息表】时底层访问抛出技术异常（如数据源不可用）
- **WHEN** 异常在更新执行中发生
- **THEN** 该技术异常按原样向调用方传播，本步骤不捕获、不转换，也不生成业务失败应答

## 验收范围与明确不覆盖的事项

验收场景是本 Spec 的测试设计依据，不是已生成的单元测试，也不是测试执行结果。

### 验收范围

- 4 条需求、11 个验收场景，覆盖：触发条件的或关系两侧与 0 边界（金额侧、笔数侧、双侧为 0）、限额检查结果非"未超限"的短路分支、按主键定位更新且同账号异场景/异账号同场景记录隔离、仅更新金额字段（笔数、客户号不变更）、更新执行与未执行两种输出口径、无业务失败与技术异常传播约定。
- 每个场景的 THEN 明确写入值、不变更字段、输出值或空值，可直接推导测试断言。

### 明确不覆盖

1. 输入必填性的校验执行及空值、非法值（如 [限额检查结果] 为 null）输入的处理——需求仅标记必填，未定义缺失或非法时的处理，由上送方保证。
2. [限额检查结果] 的取值域——需求仅使用"未超限"常量且无枚举绑定，其他取值（如示例"超限"）一律按条件不成立处理，其业务含义不定义。
3. 按主键更新未命中记录（0 行更新）时的行为与输出口径——需求未定义；仅能确定其不构成业务失败（「失败处理」声明无业务失败场景），不纳入验收断言。
4. $限额累计笔数$（字段"否"）的更新或累计——需求仅要求更新 $限额累计金额$，笔数仅参与触发条件，本 Spec 不新增笔数写入。
5. $最后修改时间戳$（LAST_UPD_TIMESTAMP）等其余字段的维护——需求未要求，不纳入本 Spec 约束与断言。
6. clientNo 输入在本步骤中的使用——步骤描述未将其用于更新定位或输出（主键不含客户号），仅作为声明的必填输入保留，无对应行为可断言。
7. 并发更新、锁与事务边界——需求未定义。
8. 更新后限额数据的后续业务使用、限额场景的维护——归属调用方及限额组件，不在本步骤范围。
9. 本需求无"组件内步骤调用"补充说明，该节约定为不适用。
