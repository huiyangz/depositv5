# ST103 检查限额场景配置是否有效

## 目标与范围

本任务为交易执行步骤：根据输入{限额机构编码}、[限额场景编码]查询【限额控制配置】取得限额控制开始/结束日期与开始/结束时间四个区间字段，检查{交易日期}、{交易时间}是否均落在对应控制区间内；均在区间内时判定限额场景配置有效，返回[限额场景编码]及四个控制区间字段，否则（含未查询到配置、任一区间字段为空、区间判定不满足）全部输出为空。

- 范围内：步骤1–2 的查询条件、控制区间字段完整性检查、交易日期与时间的区间判定、全部输出字段的取值映射与空值语义、区间比较口径。
- 不在范围内：本步骤判定结果在后续限额检查或其他交易编排中的使用；RB_LIMIT_CTRL_CONF 配置数据的建立和维护（检查限额/维护限制组件职责）；除四个控制区间字段与主键外其他配置字段（如 validFlag、limitCtrlAmt 等）的读取与使用；黑名单、检查限制、维护限制等其他检查组件。

## 正式需求来源

- `docs/requirements/ST103.md`（任务编号 ST103，版本 1，交易执行步骤）
  - 「步骤描述」步骤1「获取限额场景控制区间」、步骤2「检查交易时间」（含"任一控制区间字段为空时视为配置无效"）
  - 「输入」表（4 个字段）、「输出」表（5 个字段及空值说明）、「失败处理」
- 关联正式 Spec：无。需求未引用其他任务编号；【限额控制配置】的访问通过工程数据服务接口完成，不依赖其他任务的正式 Spec。

## 输入、输出及依赖契约

### 输入

| 字段名 | 类型 | 必填性 | 说明 |
|--------|------|--------|------|
| tranDate | java.util.Date | 必填 | 交易日期 |
| tranTimestamp | java.lang.String | 必填 | 交易时间戳，格式 HHmmss |
| limitBranchId | java.lang.String | 必填 | 限额机构编码 |
| limitSceneNo | java.lang.String | 必填 | 限额场景编码 |

需求未定义各输入缺失、为空或 tranTimestamp 格式非法时的处理（「失败处理」声明无业务失败场景），本 Spec 不发明校验或报错行为。

### 输出

| 字段名 | 类型 | 必填性 | 来源实体 | 说明 |
|--------|------|--------|----------|------|
| limitSceneNo | java.lang.String | 非必填 | 限额控制配置（RB_LIMIT_CTRL_CONF） | 限额场景编码 |
| limitCtrlBgnDate | java.util.Date | 非必填 | 限额控制配置（RB_LIMIT_CTRL_CONF） | 限额控制开始日期 |
| limitCtrlEndDate | java.util.Date | 非必填 | 限额控制配置（RB_LIMIT_CTRL_CONF） | 限额控制结束日期 |
| limitCtrlBgnTime | java.util.Date | 非必填 | 限额控制配置（RB_LIMIT_CTRL_CONF） | 限额控制开始时间 |
| limitCtrlEndTime | java.util.Date | 非必填 | 限额控制配置（RB_LIMIT_CTRL_CONF） | 限额控制结束时间 |

空值语义：仅在查询到配置、四个控制区间字段齐全且区间判定满足时，5 个输出字段取命中配置记录的值（limitSceneNo 与查询所用输入值相同，主键同值；四个区间字段取记录值）；未查询到配置、任一控制区间字段为空（配置无效）或区间判定不满足时，5 个输出字段均为空（null，不赋值）。

### 区间判定口径（比较语义）

- 「在[限额控制开始日期]、[限额控制结束日期]范围内」即闭区间：limitCtrlBgnDate ≤ tranDate ≤ limitCtrlEndDate，含两端。
- 「在[限额控制开始时间]、[限额控制结束时间]范围内」即闭区间：limitCtrlBgnTime ≤ tranTime ≤ limitCtrlEndTime，含两端；比较按当日时分秒量值进行（tranTimestamp 为 HHmmss 字符串，控制时间字段为时间量值），不含日期成分。
- 两条件须同时成立（"且"），任一不成立即走"否则"分支。

### 数据访问与依赖

- 【限额控制配置】：限额控制配置表 RB_LIMIT_CTRL_CONF，主键 (LIMIT_BRANCH_ID, LIMIT_SCENE_NO)。查询条件：limitBranchId = 输入{限额机构编码} 且 limitSceneNo = 输入[限额场景编码]（主键等值查询，至多命中一条记录，无多条处理分支）。从命中记录取 $限额控制开始日期$、$限额控制结束日期$、$限额控制开始时间$、$限额控制结束时间$。
- 技术约束：四控制区间列 DDL 类型 TIMESTAMP(3) 且均可空，映射 java.util.Date——"任一控制区间字段为空视为配置无效"正对应此可空约束。RbLimitCtrlConfEO 将 limitBranchId 类型化为 TranBranch 枚举（内部机构编号，枚举值即机构编码字符串，如"351001"），与需求输入类型 String 不冲突：本步骤输入契约以需求为准，查询按相同字符串值匹配主键；limitSceneNo 为 String。
- 本步骤为只读步骤：无外部服务调用、无组件内步骤调用、无数据写入副作用；无业务失败场景，失败仅由技术异常传播表达。
- 场景中的机构编码、场景编码与区间配置值均为示例测试数据，不代表真实字典或配置内容。

## Requirements

### Requirement: REQ-001 限额控制配置的获取

来源：`docs/requirements/ST103.md`「步骤描述」步骤1
系统 SHALL 以输入{限额机构编码}（limitBranchId）与 [限额场景编码]（limitSceneNo）为条件查询【限额控制配置】，从命中记录取得 $限额控制开始日期$、$限额控制结束日期$、$限额控制开始时间$、$限额控制结束时间$，供步骤2判定与输出使用；未查询到配置时不执行步骤2区间判定，直接返回输出：limitSceneNo 为空且四个控制区间字段均为空（null）。

#### Scenario: REQ-001-S01 按主键查到配置且四区间字段齐全→取得字段进入步骤2

- **GIVEN** limitBranchId="351001"、limitSceneNo="SC0001"（均为示例），RB_LIMIT_CTRL_CONF 中存在主键 (LIMIT_BRANCH_ID="351001", LIMIT_SCENE_NO="SC0001") 的记录，其 limitCtrlBgnDate=2026-01-01、limitCtrlEndDate=2026-12-31、limitCtrlBgnTime=09:00:00、limitCtrlEndTime=17:00:00（示例测试数据，均非空）
- **WHEN** 以 tranDate=2026-09-30、tranTimestamp="103000" 执行 ST103 步骤
- **THEN** 查询命中该条记录并取得四个控制区间字段，进入步骤2完整性检查与区间判定（最终输出按 REQ-002、REQ-003 判定）

#### Scenario: REQ-001-S02 未查询到配置→全部输出为空

- **GIVEN** limitBranchId="351001"、limitSceneNo="SC0001"（均为示例），RB_LIMIT_CTRL_CONF 中不存在主键 ("351001","SC0001") 的记录（机构与场景编码任一不匹配即无记录，如场景编码为"SC9999"）
- **WHEN** 以 tranDate=2026-09-30、tranTimestamp="103000" 执行 ST103 步骤
- **THEN** 不执行步骤2区间判定；输出 limitSceneNo 为空（null），limitCtrlBgnDate、limitCtrlEndDate、limitCtrlBgnTime、limitCtrlEndTime 均为空（null）

### Requirement: REQ-002 控制区间字段完整性检查（配置有效性）

来源：`docs/requirements/ST103.md`「步骤描述」步骤2（"任一控制区间字段为空时视为配置无效"部分）、「输出」表空值说明
系统 SHALL 在步骤2区间判定前检查已取得的控制区间字段完整性：$限额控制开始日期$、$限额控制结束日期$、$限额控制开始时间$、$限额控制结束时间$ 中任一为空（null）时视为配置无效，不执行区间判定，返回输出 limitSceneNo 为空且四个控制区间字段均为空（null）。

#### Scenario: REQ-002-S01 任一控制区间字段为空→配置无效且全部输出为空

- **GIVEN** limitBranchId="351001"、limitSceneNo="SC0001"（均为示例），RB_LIMIT_CTRL_CONF 中主键 ("351001","SC0001") 的记录存在，但 limitCtrlBgnTime 为空（null），limitCtrlBgnDate=2026-01-01、limitCtrlEndDate=2026-12-31、limitCtrlEndTime=17:00:00（示例）；tranDate=2026-09-30、tranTimestamp="103000" 本身落在其余字段构成的区间内
- **WHEN** 执行 ST103 步骤
- **THEN** 因任一控制区间字段为空判定配置无效，不执行区间判定（交易日期/时间即使落在其余字段区间内也不生效）；输出 limitSceneNo 为空（null），limitCtrlBgnDate、limitCtrlEndDate、limitCtrlBgnTime、limitCtrlEndTime 均为空（null）

### Requirement: REQ-003 交易日期与时间区间判定及结果输出

来源：`docs/requirements/ST103.md`「步骤描述」步骤2（判定与返回部分）、「输出」表
针对已查询到且四个控制区间字段齐全的配置，系统 SHALL 判定：{交易日期}（tranDate）在 [限额控制开始日期, 限额控制结束日期] 闭区间内，且 {交易时间}（tranTimestamp 的时分秒量值）在 [限额控制开始时间, 限额控制结束时间] 闭区间内（两条件同时成立）时，判定限额场景配置有效，输出 limitSceneNo（等于查询所用输入值，与命中记录同值）及 limitCtrlBgnDate、limitCtrlEndDate、limitCtrlBgnTime、limitCtrlEndTime（取命中记录值）；任一条件不成立（"否则"）时输出 limitSceneNo 为空且四个控制区间字段均为空（null）。

#### Scenario: REQ-003-S01 日期与时间均在区间内→有效并输出完整字段

- **GIVEN** RB_LIMIT_CTRL_CONF 主键 ("351001","SC0001") 记录：limitCtrlBgnDate=2026-01-01、limitCtrlEndDate=2026-12-31、limitCtrlBgnTime=09:00:00、limitCtrlEndTime=17:00:00（示例测试数据，四字段齐全）
- **WHEN** 以 tranDate=2026-09-30（严格处于两日期之间）、tranTimestamp="103000"（严格处于两时间之间）执行 ST103 步骤
- **THEN** 判定有效；输出 limitSceneNo="SC0001"、limitCtrlBgnDate=2026-01-01、limitCtrlEndDate=2026-12-31、limitCtrlBgnTime=09:00:00、limitCtrlEndTime=17:00:00（均取命中记录值）

#### Scenario: REQ-003-S02 交易日期早于开始日期→无效且输出为空

- **GIVEN** 同 REQ-003-S01 的配置记录（2026-01-01 至 2026-12-31，09:00:00 至 17:00:00）
- **WHEN** 以 tranDate=2025-12-31（早于 limitCtrlBgnDate）、tranTimestamp="103000"（在时间区间内）执行 ST103 步骤
- **THEN** 日期条件不成立，判定无效；输出 limitSceneNo 为空（null），limitCtrlBgnDate、limitCtrlEndDate、limitCtrlBgnTime、limitCtrlEndTime 均为空（null）

#### Scenario: REQ-003-S03 交易日期晚于结束日期→无效且输出为空

- **GIVEN** 同 REQ-003-S01 的配置记录
- **WHEN** 以 tranDate=2027-01-01（晚于 limitCtrlEndDate）、tranTimestamp="103000"（在时间区间内）执行 ST103 步骤
- **THEN** 日期条件不成立，判定无效；输出 limitSceneNo 为空（null），四个控制区间字段均为空（null）

#### Scenario: REQ-003-S04 交易时间早于开始时间→无效且输出为空

- **GIVEN** 同 REQ-003-S01 的配置记录
- **WHEN** 以 tranDate=2026-09-30（在日期区间内）、tranTimestamp="085959"（时分秒量值早于 09:00:00）执行 ST103 步骤
- **THEN** 时间条件不成立，判定无效；输出 limitSceneNo 为空（null），四个控制区间字段均为空（null）

#### Scenario: REQ-003-S05 交易时间晚于结束时间→无效且输出为空

- **GIVEN** 同 REQ-003-S01 的配置记录
- **WHEN** 以 tranDate=2026-09-30（在日期区间内）、tranTimestamp="170001"（时分秒量值晚于 17:00:00）执行 ST103 步骤
- **THEN** 时间条件不成立，判定无效；输出 limitSceneNo 为空（null），四个控制区间字段均为空（null）

#### Scenario: REQ-003-S06 交易日期与时间均等于区间下界→有效（闭区间含端点）

- **GIVEN** 同 REQ-003-S01 的配置记录
- **WHEN** 以 tranDate=2026-01-01（等于 limitCtrlBgnDate）、tranTimestamp="090000"（等于 limitCtrlBgnTime 的时分秒量值）执行 ST103 步骤
- **THEN** 两条件均按含端点判定成立，判定有效；输出 limitSceneNo="SC0001"、limitCtrlBgnDate=2026-01-01、limitCtrlEndDate=2026-12-31、limitCtrlBgnTime=09:00:00、limitCtrlEndTime=17:00:00

#### Scenario: REQ-003-S07 交易日期与时间均等于区间上界→有效（闭区间含端点）

- **GIVEN** 同 REQ-003-S01 的配置记录
- **WHEN** 以 tranDate=2026-12-31（等于 limitCtrlEndDate）、tranTimestamp="170000"（等于 limitCtrlEndTime 的时分秒量值）执行 ST103 步骤
- **THEN** 两条件均按含端点判定成立，判定有效；输出 limitSceneNo="SC0001"、limitCtrlBgnDate=2026-01-01、limitCtrlEndDate=2026-12-31、limitCtrlBgnTime=09:00:00、limitCtrlEndTime=17:00:00

## 验收范围与明确不覆盖的事项

### 验收范围

- 3 条需求、10 个验收场景，覆盖：查询命中的正常路径、未查询到配置的空输出路径、任一区间字段为空的配置无效边界、日期早于/晚于区间的时间越界与时间早于/晚于区间的日期在范围内分支、日期与时间同时等于下界/上界的闭区间含端点边界。
- 每个"有效"场景的 THEN 明确全部 5 个输出字段的取值（limitSceneNo 及四个区间字段取命中记录值），每个"无效/未查到"场景的 THEN 明确 5 个输出字段均为空（null），可直接推导测试断言。

### 明确不覆盖

- 输入缺失、为空或 tranTimestamp 格式非法（非 HHmmss）时的处理：需求标记必填但未定义校验行为，且声明无业务失败场景，本 Spec 不发明。
- 控制时间区间跨零点（开始时间晚于结束时间）的特殊语义：需求未定义，按闭区间时分秒量值比较的直接结果判定，不发明跨日回绕。
- RB_LIMIT_CTRL_CONF 其他字段（validFlag、limitCtrlAmt、periodType 等）的读取、过滤与使用：需求仅取四个区间字段与主键，本 Spec 不引入（如需求未要求按 validFlag 过滤，查询即不含该条件）。
- 判定结果（有效限额场景编码及区间字段）在后续限额检查步骤或交易编排中的使用，以及配置数据的建立与维护。
- 技术异常（如数据访问异常）的传播与包装方式：需求声明失败仅由技术异常传播表达，不属于验收场景范围。
- 本任务无组件内步骤调用补充说明，该约定为不适用。
