# ST093 检查存入账户账户属性

## 目标与范围

本步骤为交易执行步骤：根据输入{账号}查询【账户信息】取得$账户属性$；若[账户属性]为"验资户"或"临时存款账户"，本步骤输出[账户属性]并正常返回（交易编排依据该输出跳转至步骤《检查账户到期日》）；否则返回检查结果为"通过"，即正常返回且不输出账户属性。

范围内：

- 按 baseAcctNo 等值查询【账户信息】取得 $账户属性$（acctNatureNo）
- [账户属性] 为"验资户"或"临时存款账户"时，输出 acctNatureNo 并正常返回
- [账户属性] 为其他取值时，正常返回且不输出 acctNatureNo（检查结果"通过"）
- 失败仅由技术异常向上传播表达

不在范围内的事项见「验收范围与明确不覆盖的事项」。

## Requirements

### Requirement: REQ-001 按账号获取账户属性
来源：docs/requirements/ST093.md「步骤描述」第 1 条
系统 SHALL 以输入 baseAcctNo 为条件等值查询【账户信息】（RB_BUS_ACCT），取得该账户记录的 $账户属性$（acctNatureNo）作为待检查的[账户属性]；库存值 MUST 按枚举 value 与 com.dcits.depsit.enums.AcctNatureNo 一致映射。

#### Scenario: REQ-001-S01 按账号查得账户属性
- **GIVEN** 【账户信息】中存在 BASE_ACCT_NO='ACCT1001'（示例值）的一条记录，ACCT_NATURE_NO='11003'
- **WHEN** 执行本步骤，输入 baseAcctNo='ACCT1001'
- **THEN** 取得该记录的账户属性，[账户属性] = AcctNatureNo.VALUE_11003（value "11003"）

### Requirement: REQ-002 账户属性为验资户或临时存款账户时输出账户属性并正常返回
来源：docs/requirements/ST093.md「步骤描述」第 2 条（前半句）、「输出」
当[账户属性]等于"验资户"（AcctNatureNo.VALUE_17）或"临时存款账户"（AcctNatureNo.VALUE_11003）时，系统 SHALL 将该[账户属性]赋值到输出 acctNatureNo 并正常返回：succeed=true，不设置错误码与错误信息。向步骤《检查账户到期日》的跳转由交易编排依据该输出执行，本步骤 MUST NOT 承担该跳转。

#### Scenario: REQ-002-S01 账户属性为验资户
- **GIVEN** 按 REQ-001 取得 [账户属性] = AcctNatureNo.VALUE_17（库存值 '17'）
- **WHEN** 执行检查并返回
- **THEN** 输出 acctNatureNo=AcctNatureNo.VALUE_17；succeed=true；errorCode、errorMessage 均为 null

#### Scenario: REQ-002-S02 账户属性为临时存款账户
- **GIVEN** 按 REQ-001 取得 [账户属性] = AcctNatureNo.VALUE_11003（库存值 '11003'）
- **WHEN** 执行检查并返回
- **THEN** 输出 acctNatureNo=AcctNatureNo.VALUE_11003；succeed=true；errorCode、errorMessage 均为 null

### Requirement: REQ-003 其他账户属性返回检查结果"通过"
来源：docs/requirements/ST093.md「步骤描述」第 2 条（"否则返回检查结果为'通过'"）、「输出」
当[账户属性]既不等于"验资户"也不等于"临时存款账户"时，系统 SHALL 正常返回且不输出账户属性：输出 acctNatureNo 为 null，succeed=true，不设置错误码与错误信息；此即检查结果"通过"的表达（依据「输出」仅含非必填的 acctNatureNo，无独立检查结果字段）。

#### Scenario: REQ-003-S01 账户属性为其他取值时不输出账户属性
- **GIVEN** 按 REQ-001 取得 [账户属性] = AcctNatureNo.VALUE_11001（基本存款账户，库存值 '11001'，示例值），不属于"验资户"或"临时存款账户"
- **WHEN** 执行检查并返回
- **THEN** 输出 acctNatureNo=null（不输出账户属性）；succeed=true；errorCode、errorMessage 均为 null；本步骤为成功返回，不构成业务失败

### Requirement: REQ-004 失败仅由技术异常传播表达
来源：docs/requirements/ST093.md「失败处理」（"本步骤无业务失败场景，失败仅由技术异常传播表达"）
本步骤 SHALL NOT 定义任何业务失败场景；失败 SHALL 仅由技术异常向上传播表达，本步骤不捕获、不转换。

#### Scenario: REQ-004-S01 数据访问技术异常向上传播
- **GIVEN** 查询【账户信息】时底层访问抛出技术异常（如数据源不可用）
- **WHEN** 执行本步骤
- **THEN** 该技术异常按原样向上传播，本步骤不捕获、不转换，也不生成业务失败应答

## 验收范围与明确不覆盖的事项

验收场景是本 Spec 的测试设计依据，不是已生成的单元测试，也不是测试执行结果。

明确不覆盖：

1. 【账户信息】中无该账号记录、或记录 ACCT_NATURE_NO 为空时的行为：需求第 2 步分支以取得[账户属性]为前提，未定义该情形归属哪个分支，不纳入验收。
2. 同一账号在 RB_BUS_ACCT 存在多条记录时的取舍规则：需求按单一账户记录表述，未定义多条取舍，不纳入验收。
3. 向《检查账户到期日》跳转的判定与执行：需求明示由交易编排依据本步骤输出承担，非本步骤行为，不纳入本步骤验收。
4. baseAcctNo 缺失或为空时的校验行为：需求仅标记必填，必填性由上送方保证，不纳入验收。
5. 账户属性各取值的业务解释及验资户/临时存款账户之外属性的后续处置：非本步骤要求，不纳入验收。
