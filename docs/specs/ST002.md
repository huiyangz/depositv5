# ST002 检查限制豁免

## 目标与范围

本任务为存款业务组件（deposit-service，包名 com.dcits.depsit）内的交易执行步骤。目标：依据渠道类型、账户限制类型、交易类型、摘要码、产品类型，查询渠道类型表（FM_CHANNEL）与存款限制检查控制详情表（RB_RESTRAINT_CONTROL_DETAILS），按子步骤 1–5 判定该笔交易针对账户限制检查的豁免结果，返回检查结果 checkResult（不检查限制 / 需检查限制 / 豁免 / 不豁免），并输出渠道柜面标志及匹配明细的回填字段。

范围内：

- 子步骤 1（获取渠道柜面标志）、子步骤 2（获取生效限制控制明细）、子步骤 3（柜面标志路由）、子步骤 4（柜面渠道豁免检查）、子步骤 5（非柜面渠道豁免检查）的查询条件、控制流与结果映射；
- 输出字段取值规则：匹配明细字段的回填、无匹配时置空、无渠道记录时柜面标志按 "N"；
- 三项同时匹配规则的口径（多交易类型包含交易代码、摘要码相等、产品类型相等）；
- 无业务失败场景前提下的技术异常传播。

不在范围内的事项见"验收范围与明确不覆盖的事项"。

| channelMuster | java.lang.String | 存款限制检查控制详情（RB_RESTRAINT_CONTROL_DETAILS） | 匹配明细的渠道集合；无匹配时为空。仅回填，不参与匹配判定 |

需求输出表将全部字段标注"非必填"；按正文行为，counterFlag 与 checkResult 在步骤成功执行时恒有值，来源为 RB_RESTRAINT_CONTROL_DETAILS 的七个字段取决于是否存在同时匹配的明细（有匹配回填、无匹配为空，见输出说明）。

### 三项同时匹配规则（子步骤 4 / 子步骤 5 共用）

一条[限制控制明细信息]与{交易类型}、{摘要码}、{产品类型}同时匹配，当且仅当同时满足：

1. $多交易类型$（tranTypeLink，String）包含 {交易类型}（tranType）的对应代码值（字符串包含）；
2. $摘要码$（narrativeCode）与输入 {摘要码}（narrativeCode）按字面相等；
3. $产品类型$（prodNo）与输入 {产品类型}（prodNo）按字面相等。

匹配判定仅依据上述三项，渠道集合（channelMuster）等其余明细字段不参与。需求未定义多交易类型字符串的内部分隔格式，本 Spec 按字面"包含代码值"表达（见不覆盖事项 4）。

### 子步骤控制流与口径说明

- 路由（子步骤 3）：渠道柜面标志（子步骤 1 的 counterFlag）等于 "Y" 且 生效明细的柜面标志等于 "Y" → 子步骤 4；否则 → 子步骤 5。
- 口径说明 1（子步骤 5 的适用情形）：子步骤 3 的"否则"明确包含"渠道柜面标志 = Y 且 生效明细柜面标志 ≠ Y（含无生效明细）"的情形；子步骤 5 首句"渠道类型对应的柜面标志等于 N-否 时"与其子步骤名称"检查非柜面渠道的豁免信息"一致，是对该子步骤典型适用情形的说明。结合失败处理"本步骤无业务失败场景"（凡完成执行的路径必有检查结果），凡经子步骤 3"否则"进入子步骤 5 的情形均按子步骤 5 的匹配规则返回 豁免 / 不豁免。
- 口径说明 2（明细柜面标志按单一取值使用）：需求以"账户限制类型对应的[柜面标志]"单值口径使用该字段，输出说明亦以"那条"单条口径描述匹配明细。同一账户限制类型下状态生效明细的柜面标志存在多个不同取值时，路由判定口径需求未定义，本 Spec 不覆盖（见不覆盖事项 2）；范围内场景按生效明细柜面标志取值一致构造数据，此时"生效明细的柜面标志"即该一致取值。
- 口径说明 3（无生效明细）：生效明细集合为空时，"账户限制类型对应的柜面标志"不存在，子步骤 3 条件不成立，进入子步骤 5；匹配判定无候选明细，按无匹配处理。

### 依赖调用

| 调用位置 | 数据服务接口（均已存在） | 入参 | 结果用途 |
|----------|--------------------------|------|----------|
| 子步骤 1 | IFmChannelBcc.findByChannel(SourceType channel) | sourceType | 取返回 FmChannelEO.counterFlag 作为渠道柜面标志；返回 null（无对应记录）时柜面标志按 "N" |
| 子步骤 2 | IRbRestraintControlDetailsBcc.findByEo(RbRestraintControlDetailsEO eo) | EO 仅设置 restraintType 与 status = Status.A（按非空属性等值过滤） | 返回生效明细集合，用于子步骤 3 路由、子步骤 4/5 匹配判定及输出字段回填 |

无组件内步骤调用，无平台服务依赖。失败处理：本步骤无业务失败场景，上述数据服务的技术异常原样向上传播（REQ-006）。

### 枚举与表核对结论

- 需求引用的五个枚举类均已存在于 `deposit-common/src/main/java/com/dcits/depsit/enums/`：SourceType（138 项）、RestraintType（100 项）、OthTranType（2000 项）为代码集枚举，场景中取示例值；Status、ResBranchRange 为带语义枚举。代码值比较均可表达，无缺失。
- 标签同义差异（以代码值为准，不构成冲突）：需求"A-生效"对应 Status.A（枚举注释"有效"），代码值均为 "A"；需求正文"渠道类型定义表"即输出表的"渠道类型表（FM_CHANNEL）"，"限制控制明细表"即"存款限制检查控制详情（RB_RESTRAINT_CONTROL_DETAILS）"。
- RbRestraintControlDetailsEO 字段与七个明细回填输出字段一一对应（counterFlag 输出名 detailCounterFlag）；FmChannelEO.counterFlag 与渠道柜面标志输出对应。该表主键为（产品编号、表达式、多交易类型、账户限制类型、是否批量、柜面标志），故同一限制类型可存在多条生效明细。

## Requirements

### Requirement: REQ-001 获取渠道柜面标志
来源：docs/requirements/ST002.md 步骤描述 1
系统 SHALL 根据输入 sourceType（渠道类型）查询渠道类型表（FM_CHANNEL），取对应记录的柜面标志并输出 counterFlag；FM_CHANNEL 无 sourceType 对应记录时，系统 SHALL 将柜面标志按 "N-否" 处理，输出 counterFlag = "N"，且 SHALL 继续执行子步骤 2（无记录不构成失败）。柜面标志取值仅取决于 FM_CHANNEL 记录，与渠道枚举项的业务含义无关；"Y" / "N" 为规范常量。

#### Scenario: REQ-001-S01 渠道有记录时取表内柜面标志
- **GIVEN** FM_CHANNEL 存在渠道 = SourceType.MT（示例：Teller9 综合柜员前端柜面系统）的记录，其柜面标志为 "Y"
- **WHEN** 执行步骤 ST002，输入 sourceType = SourceType.MT（其余输入为满足必填的任意合法值）
- **THEN** 输出 counterFlag = "Y"，继续执行子步骤 2（后续按 REQ-002 ~ REQ-005 执行）

#### Scenario: REQ-001-S02 渠道无记录时柜面标志按 N 处理
- **GIVEN** FM_CHANNEL 不存在渠道 = SourceType.M（示例：手机银行）的记录
- **WHEN** 执行步骤 ST002，输入 sourceType = SourceType.M
- **THEN** 输出 counterFlag = "N"，继续执行子步骤 2，不产生业务失败

### Requirement: REQ-002 获取状态生效的限制控制明细
来源：docs/requirements/ST002.md 步骤描述 2
系统 SHALL 根据输入 restraintType（账户限制类型）查询限制控制明细表（RB_RESTRAINT_CONTROL_DETAILS），取 $状态$ 等于 "A-生效"（Status.A）的[限制控制明细信息]集合，明细包括 $产品类型$（prodNo）、$多交易类型$（tranTypeLink）、$渠道集合$（channelMuster）、$摘要码$（narrativeCode）、$限制机构范围$（resBranchRange）、$柜面标志$（输出名 detailCounterFlag）。无状态为 A 的记录（该限制类型无记录或记录状态均非 A）时集合为空，系统 SHALL 继续执行子步骤 3（空集不构成失败）。

#### Scenario: REQ-002-S01 存在状态生效的限制控制明细
- **GIVEN** RB_RESTRAINT_CONTROL_DETAILS 存在 restraintType = RestraintType.VALUE_13（"13"，示例：挂失止付）且 status = Status.A 的明细（示例：prodNo = "101001"、narrativeCode = "1001"、tranTypeLink = "36,38,40"、channelMuster = "MT,M"、resBranchRange = ResBranchRange.A、counterFlag = "Y"）
- **WHEN** 执行步骤 ST002，输入 restraintType = RestraintType.VALUE_13
- **THEN** 生效明细集合包含该条记录，继续执行子步骤 3（明细字段取值待子步骤 4/5 匹配后回填）

#### Scenario: REQ-002-S02 无状态生效明细时集合为空
- **GIVEN** RB_RESTRAINT_CONTROL_DETAILS 中 restraintType = RestraintType.VALUE_13 仅有 status = Status.C（示例：非生效状态）的记录，或无该限制类型的任何记录
- **WHEN** 执行步骤 ST002，输入 restraintType = RestraintType.VALUE_13
- **THEN** 生效明细集合为空，继续执行子步骤 3，不产生业务失败

### Requirement: REQ-003 按渠道与明细柜面标志路由豁免检查
来源：docs/requirements/ST002.md 步骤描述 3
系统 SHALL 在渠道柜面标志（counterFlag）等于 "Y-是" 且 生效明细的柜面标志等于 "Y-是" 时执行子步骤 4（检查柜面渠道的豁免信息）；否则（含渠道柜面标志为 "N"、生效明细柜面标志非 "Y"、无生效明细）SHALL 执行子步骤 5（检查非柜面渠道的豁免信息）。路由结果通过所执行子步骤返回的检查结果取值集合可观察：子步骤 4 → {不检查限制, 需检查限制}，子步骤 5 → {豁免, 不豁免}。生效明细柜面标志按单一取值口径使用（见口径说明 2）。

#### Scenario: REQ-003-S01 渠道与明细均柜面时走柜面豁免检查
- **GIVEN** 子步骤 1 取得渠道柜面标志 counterFlag = "Y"；生效明细柜面标志 = "Y"；存在与{交易类型}、{摘要码}、{产品类型}同时匹配的明细
- **WHEN** 执行步骤 ST002
- **THEN** 执行子步骤 4，检查结果取值属于 {不检查限制, 需检查限制}（本示例数据下返回"不检查限制"，见 REQ-004-S01）

#### Scenario: REQ-003-S02 渠道非柜面时走非柜面豁免检查
- **GIVEN** 渠道柜面标志 counterFlag = "N"（含 FM_CHANNEL 无记录按 "N" 处理的情形）；生效明细柜面标志 = "Y"；存在三项同时匹配的明细
- **WHEN** 执行步骤 ST002
- **THEN** 执行子步骤 5，检查结果取值属于 {豁免, 不豁免}（本示例数据下返回"豁免"，见 REQ-005）

#### Scenario: REQ-003-S03 渠道柜面而明细非柜面时走非柜面豁免检查
- **GIVEN** 渠道柜面标志 counterFlag = "Y"；生效明细柜面标志 = "N"；存在三项同时匹配的明细
- **WHEN** 执行步骤 ST002
- **THEN** 执行子步骤 5，返回"豁免"（子步骤 3"否则"路由，见口径说明 1 与 REQ-005-S03）

#### Scenario: REQ-003-S04 渠道柜面且无生效明细时走非柜面豁免检查
- **GIVEN** 渠道柜面标志 counterFlag = "Y"；生效明细集合为空
- **WHEN** 执行步骤 ST002
- **THEN** 执行子步骤 5，返回"不豁免"（无匹配候选，见口径说明 3 与 REQ-005-S04）

### Requirement: REQ-004 柜面渠道豁免检查与明细回填
来源：docs/requirements/ST002.md 步骤描述 4（含匹配规则括注）
执行子步骤 4 时，系统 SHALL 判定生效明细集合中是否存在与{交易类型}、{摘要码}、{产品类型}同时匹配的明细（$多交易类型$包含{交易类型}对应代码值；$摘要码$、$产品类型$按字面相等），存在时返回 checkResult = "不检查限制"，否则返回 checkResult = "需检查限制"。返回"不检查限制"时，输出中来源为 RB_RESTRAINT_CONTROL_DETAILS 的七个字段（status、prodNo、tranTypeLink、channelMuster、narrativeCode、resBranchRange、detailCounterFlag）SHALL 取该匹配明细的对应值；无同时匹配明细时这七个字段 SHALL 为空。匹配判定 SHALL 仅依据上述三项，$渠道集合$等其余明细字段不参与。

#### Scenario: REQ-004-S01 三项同时匹配返回不检查限制并回填明细字段
- **GIVEN** 渠道柜面标志 counterFlag = "Y"，生效明细柜面标志 = "Y"；生效明细含一条：tranTypeLink = "36,38,40"、narrativeCode = "1001"、prodNo = "101001"、status = Status.A、channelMuster = "MT,M"、resBranchRange = ResBranchRange.A、counterFlag = "Y"；输入 tranType = OthTranType.VALUE_38（"38"，示例）、narrativeCode = "1001"、prodNo = "101001"
- **WHEN** 执行步骤 ST002
- **THEN** checkResult = "不检查限制"；counterFlag = "Y"；status = Status.A（代码值 "A"）；prodNo = "101001"；tranTypeLink = "36,38,40"；channelMuster = "MT,M"；narrativeCode = "1001"；resBranchRange = ResBranchRange.A；detailCounterFlag = "Y"

#### Scenario: REQ-004-S02 无同时匹配明细返回需检查限制且明细字段为空
- **GIVEN** 路由条件同 REQ-004-S01；生效明细仅一条：tranTypeLink = "36,38,40"、narrativeCode = "1002"、prodNo = "101001"（摘要码与输入不等）；输入 tranType = OthTranType.VALUE_38、narrativeCode = "1001"、prodNo = "101001"
- **WHEN** 执行步骤 ST002
- **THEN** checkResult = "需检查限制"；来源为 RB_RESTRAINT_CONTROL_DETAILS 的七个输出字段均为空；counterFlag = "Y"

#### Scenario: REQ-004-S03 多交易类型不包含交易代码返回需检查限制
- **GIVEN** 路由条件同 REQ-004-S01；生效明细仅一条：tranTypeLink = "36,40"（不包含代码值 "38"）、narrativeCode = "1001"、prodNo = "101001"；输入 tranType = OthTranType.VALUE_38、narrativeCode = "1001"、prodNo = "101001"
- **WHEN** 执行步骤 ST002
- **THEN** checkResult = "需检查限制"；来源为 RB_RESTRAINT_CONTROL_DETAILS 的七个输出字段均为空

#### Scenario: REQ-004-S04 产品类型不相等返回需检查限制
- **GIVEN** 路由条件同 REQ-004-S01；生效明细仅一条：tranTypeLink = "36,38,40"、narrativeCode = "1001"、prodNo = "101002"；输入 tranType = OthTranType.VALUE_38、narrativeCode = "1001"、prodNo = "101001"
- **WHEN** 执行步骤 ST002
- **THEN** checkResult = "需检查限制"；来源为 RB_RESTRAINT_CONTROL_DETAILS 的七个输出字段均为空

### Requirement: REQ-005 非柜面渠道豁免检查与明细回填
来源：docs/requirements/ST002.md 步骤描述 5（含口径说明 1、3）
凡经子步骤 3"否则"进入子步骤 5 的情形（渠道柜面标志为 "N"；或渠道柜面标志为 "Y" 而生效明细柜面标志非 "Y" 或无生效明细），系统 SHALL 按与 REQ-004 相同的三项同时匹配规则判定生效明细集合：存在同时匹配的明细时返回 checkResult = "豁免"，否则（含生效明细集合为空）返回 checkResult = "不豁免"。返回"豁免"时，来源为 RB_RESTRAINT_CONTROL_DETAILS 的七个字段（status、prodNo、tranTypeLink、channelMuster、narrativeCode、resBranchRange、detailCounterFlag）SHALL 取该匹配明细的对应值；返回"不豁免"时这七个字段 SHALL 为空。

#### Scenario: REQ-005-S01 渠道非柜面且三项匹配返回豁免并回填明细字段
- **GIVEN** FM_CHANNEL 渠道记录柜面标志 counterFlag = "N"；生效明细柜面标志 = "N"，仅一条：tranTypeLink = "36,38,40"、narrativeCode = "1001"、prodNo = "101001"、status = Status.A、channelMuster = "M"、resBranchRange = ResBranchRange.C、counterFlag = "N"；输入 tranType = OthTranType.VALUE_38、narrativeCode = "1001"、prodNo = "101001"
- **WHEN** 执行步骤 ST002
- **THEN** checkResult = "豁免"；counterFlag = "N"；status = Status.A；prodNo = "101001"；tranTypeLink = "36,38,40"；channelMuster = "M"；narrativeCode = "1001"；resBranchRange = ResBranchRange.C；detailCounterFlag = "N"

#### Scenario: REQ-005-S02 渠道非柜面且无同时匹配返回不豁免
- **GIVEN** 路由条件同 REQ-005-S01（渠道柜面标志 "N"）；生效明细仅一条：tranTypeLink = "36,38,40"、narrativeCode = "1002"、prodNo = "101001"；输入 narrativeCode = "1001"（其余输入同 REQ-005-S01）
- **WHEN** 执行步骤 ST002
- **THEN** checkResult = "不豁免"；来源为 RB_RESTRAINT_CONTROL_DETAILS 的七个输出字段均为空；counterFlag = "N"

#### Scenario: REQ-005-S03 渠道柜面而明细非柜面且三项匹配返回豁免
- **GIVEN** FM_CHANNEL 渠道记录柜面标志 counterFlag = "Y"；生效明细柜面标志 = "N"，明细数据同 REQ-005-S01（三项与输入同时匹配）；输入同 REQ-005-S01
- **WHEN** 执行步骤 ST002
- **THEN** checkResult = "豁免"（经子步骤 3"否则"进入子步骤 5，见口径说明 1）；来源为 RB_RESTRAINT_CONTROL_DETAILS 的七个输出字段取该匹配明细对应值（detailCounterFlag = "N"）；counterFlag = "Y"

#### Scenario: REQ-005-S04 渠道柜面且无生效明细返回不豁免
- **GIVEN** FM_CHANNEL 渠道记录柜面标志 counterFlag = "Y"；RB_RESTRAINT_CONTROL_DETAILS 无该限制类型状态为 A 的记录
- **WHEN** 执行步骤 ST002（输入满足必填）
- **THEN** checkResult = "不豁免"；来源为 RB_RESTRAINT_CONTROL_DETAILS 的七个输出字段均为空；counterFlag = "Y"

### Requirement: REQ-006 无业务失败场景与技术异常传播
来源：docs/requirements/ST002.md 失败处理
本步骤 SHALL 不定义任何业务失败场景与业务失败返回；访问 FM_CHANNEL 或 RB_RESTRAINT_CONTROL_DETAILS 数据服务发生的技术异常 SHALL 原样向上传播，不捕获转换、不产生检查结果。

#### Scenario: REQ-006-S01 数据服务技术异常向上传播
- **GIVEN** 底层数据服务访问（子步骤 1 或子步骤 2）抛出技术异常（如数据库访问异常）
- **WHEN** 执行步骤 ST002
- **THEN** 该技术异常原样向上传播，本步骤不返回 checkResult 等业务输出

## 验收范围与明确不覆盖的事项

1. 输入五个字段均为必填；空值 / null 输入的行为需求未定义，由上游保证，本 Spec 不增设校验或默认值。
2. 同一账户限制类型下状态生效明细的柜面标志存在多个不同取值时，子步骤 3"账户限制类型对应的[柜面标志]"的判定口径需求未定义（见口径说明 2），本 Spec 不覆盖；验收场景按生效明细柜面标志取值一致构造。
3. 多条明细与{交易类型}、{摘要码}、{产品类型}同时匹配时，输出明细字段取哪一条需求未规定（检查结果本身不受影响，按"存在匹配"判定）；验收场景按单一匹配构造。
4. $多交易类型$字符串的内部分隔格式及代码值前缀歧义（如 "38" 与 "3810" 同时存在时 "38" 是否视为包含于 "3810"）需求未定义；本 Spec 按字面"字符串包含代码值"表达，验收数据应避免前缀歧义。
5. FM_CHANNEL 柜面标志取 "Y"/"N" 以外值的行为需求未定义（正文按二值使用），不覆盖。
6. $渠道集合$（channelMuster）不参与匹配判定（需求匹配条件仅三项），仅作为匹配明细字段回填输出。
7. 本步骤仅产出检查结果与字段回填，不执行后续账户限制检查，不读写维护限制数据，不涉及限额、黑名单检查。
8. 业务失败场景：无。失败仅由技术异常传播表达（REQ-006），不涉及重试、降级或补偿。
